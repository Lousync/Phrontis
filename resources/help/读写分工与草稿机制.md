# 核心概念：读写分工与收录规则

**两条基本规则**：正文**只能在中间区的编辑页签里写**，侧栏（左栏、知识库侧栏）只负责浏览与文件管理；仓库里的 Markdown 文件**都会进知识库**，**不需要你手动加任何元数据**。

## 一、读写分工

| | 中间区编辑页签 | 侧栏（左栏文件树 / 知识库侧栏） |
|---|---|---|
| 职责 | **写正文**：编辑内容、续写、加标签 | **管文件**：新建、重命名、移动、删除、浏览 |
| 操作对象 | 磁盘上的 `.md` 文件（仓库里的真实文件） | 同一批文件，以目录树呈现 |
| 能不能写正文 | 能（唯一入口） | **不能**（有意设计，不是缺失） |

侧栏可以**新建文件 / 文件夹 / 知识页**（右键菜单或头部「＋」），建完点开就在中间区的编辑页签里写内容。**「新建」在侧栏里找得到，「写正文」只在中间区**——两者不是一回事。

## 二、收录规则：Markdown 都会进知识库

仓库里每个未忽略的 `.md` 文件都是知识库条目。首次保存时软件**自动补上 `id` 等身份字段**，你**不需要手写 frontmatter**。写好的笔记会立刻出现在全文检索、双链与知识图谱里。

**Phrontis 没有「草稿」概念**：不存在「只在编辑器可见、知识库看不到」的文件类型。要排除某文件，用 `.ignore` 规则，而不是靠有没有 `id`。

## 三、写了文件但知识库看不到：三步排查

1. 确认文件**保存在当前打开的仓库文件夹内**；
2. 检查是否被仓库根的 `.ignore` 规则命中（gitignore 语法；被忽略的文件会从列表、检索、图谱与 AI 检索里**彻底消失**，文件本身仍在磁盘上）；
3. 刚在系统资源管理器里改动过 → 通常 **1 秒内自动跟上**；迟迟不动再切一下模块（索引按需重建）。

## 常见误用

- 以为「看不到 = 没加 frontmatter id」→ 现在不需要手写 `id`，看不到多半是 `.ignore` 命中或文件不在当前仓库内；
- 想用改名绕过 `.ignore` → 规则按路径匹配，改名不一定有效，改规则才是正解；
- 以为「知识库看不到 = 文件丢了」→ 打开仓库文件夹即可看到真实文件；
- 手动写入的 `id` 一旦确定**不要手改**（改名会让双链与反向链接失配）。
