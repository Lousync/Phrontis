## 一、职责边界（已拍板）

| | 编辑器模块 | 知识库模块 |
|---|---|---|
| 职责 | **唯一内容写入方**：Monaco 编辑正文 + frontmatter | **读取方 + 结构维护者**（2026-09-07 演进）：沉浸阅读、刷题/错题本、双链跳转+反链、标签/收藏/搜索；建删目录/空间/笔记本、导入、重命名、排序 |
| 文件范围 | 仓库里一切文件 | 只有带 frontmatter id 的知识页 |
| 附件/PDF | 二进制拒开 | 预览、注解都在这 |

- **Vault = 唯一真相源**。数据库降为索引（knowledgeIndex），最终 P5 移除。
- 无 frontmatter id 的文件 = 普通文件（编辑器草稿），知识库列表不显示（对标 Obsidian 非笔记文件）。

## 二、已拍板的三个决定（2026-09-02）

1. **星标/标签小编辑留在知识库阅读器**（例外而非常态）：走 frontmatter 重写、正文不动，mtime 冲突检测兜底。
2. **双链语法**：与图论文档（graph-view-design.md）一起讨论后拍板，暂缓。
3. **编辑器 v1 保持裸文本 + 跳转闭环**：不做 `[[` 补全、链接高亮、大纲面板，挂账阶段 2（届时以 Monaco completion provider 接同一套双链解析）。

## 三、跳转闭环协议

```
知识库「在编辑器中打开」
  → getKnowledgePageById(id) 得 payload.path（仓库内相对路径）
  → window.dispatchEvent(CustomEvent('kb-open-in-editor', { detail: { relPath } }))
  → App.tsx 监听：切到 editor Tab
  → EditorModule 监听：无仓库时 workspaceGetCurrent 恢复当前仓库 → openFile
编辑器 Ctrl+S
  → ws:writeFile → 索引失效钩子（写/建/改名/删 4 通道）
  → 知识库 Tab 激活时重读索引（保活架构硬约束，所有读 Vault 模块遵守）
```

- 渲染层只传 `{ relPath }`（仓库内相对路径），绝不接触绝对路径。
- sqlite 读源模式下跳转按钮不渲染（该模式下知识库自身可编辑）。

## 四、vault 读源模式行为矩阵（storage.knowledge = vault）

| 类别 | 通道 | 行为 |
|---|---|---|
| 读 | getCategories / getPages / getPageById / searchPages / getStarredPages / getTags | 走 knowledgeIndex + 读 .md |
| 写（已拍板例外） | toggleStar | frontmatter 重写（保正文），索引失效 |
| 其余全部 | createPage / deletePage / movePage / duplicate / 分类增删改 / 手动关联 / updateLinks 等 | **友好拒绝**：「仓库读源模式下请在编辑器模块编辑内容」——防止 SQLite 与 Vault 静默分叉 |

- 标签：vault 模式下从页面 frontmatter `tags` 聚合（color 置空），标签管理类操作拒绝。
- 已知边界（后续补）：importRepo / quizRepo 的知识页写通道在 vault 模式的拦截；编辑器「新建知识页」需带 frontmatter id 模板。
