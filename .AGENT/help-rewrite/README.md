## 一、定位（一句话）

**手册的唯一真实读者是 AI（`builtin.help.search`），用户几乎不看。** 重编目标不是「写得好看」，而是「AI 检索必中、片段自足、事实不过期」。帮助中心照常渲染这些 md，那是副产品，不是优化目标。

### 片段经济学（写作规范的四条硬约束，源自 helpRetrieval.ts 的真实行为）

1. **AI 实际读到的是「命中位置前后约 700 字符的片段」**（`snippetOf` span=700）→ 每篇拆成**问答式短节**，每节 ≤300 字自足，保证片段落在完整答案里，而不是答案的一半。
2. **按 id 精读只返回前 4000 字符** → 单篇正文 ≤3500 字符，写多了 AI 读不到。
3. **检索按 bigram 字面匹配**（标题 10 分 > keywords 6 分 > 正文 1 分）→ 按钮、菜单、功能名一律用 **UI 上的字面词**；口语别名写进 frontmatter `keywords`。
4. **「不支持什么」必须显式写** —— AI 编造软件行为是最大事故源，负向信息（无云、侧栏不能写正文、X 不支持 Y）要单独成句。

### 语气规范（2026-09-28 用户定调，全批次适用）

**规范书面语，禁俏皮口语**——文档唯一读者是 AI，口语化表达（「不是聊天摆设」「别信」「它笨」「会不会越权？」式反问）会直接进入 AI 的回答语料。统一写法：陈述句 + 名词化表述；「担心/别信/压根」→「若需了解/不要采信/完全」；示例问法保留（帮 AI 做问句→功能映射），但引导语用「典型问法：」。

**规格式结构（2026-09-28 二次定调）**——用户文档惯性（开场引导、跨节指路、叙事流）对 AI 语料是反模式：
1. 每节**直接以事实开头**，无「一句话定位」式铺垫；标题即检索锚点，高频问句单独立节（如「AI 说改完了但界面没变」）；
2. **禁跨节指代**（「下面清单」「上列工具」「这一节」）——AI 只读命中位置前后约 700 字符的片段，指代词在片段里是空指，每节必须自足，必要的事实宁可重复；
3. 陈述全部写成「主语-谓语-数值/路径」规格式，一段一个断言；bold 只标术语与档位名，不做强调修辞；
4. 首节（# 标题下第一段）= 全篇摘要：是什么 + 入口路径 + 覆盖什么，无指代。

### 篇目路由：frontmatter `desc` + 工具自动目录（2026-09-28 定调，替代「相关篇章」节）

各篇**不再写「相关篇章」节**（23 篇各抄一份路由 = 清单漂移高发区）。路由信息收敛为：

1. **每篇 frontmatter 加一行 `desc: 一句话概括该篇覆盖什么主题`**（只写主题不写行为细节，防漂移）——这是篇目描述的唯一真相源；
2. **机制侧待办（N-10 落码时一并做）**：`helpService.searchHelpIn` 返回结果附带全部篇目目录（id + title + desc，磁盘现读自动聚合，零维护）——AI 每次调 help.search 都自带路由，不再依赖任何手工清单；
3. 人类用户的篇目导航由帮助中心分类树 + 《模块一览》（模块入口索引）承载，不单开导航篇。

已应用：《快速上手》《AI 权限与工具边界》已删「相关篇章」节并补 `desc`。

### frontmatter 规范

```yaml
---
title: 篇名（必填，检索 10 分档）
category: 入门（沿用现有分组名）
keywords: [口语别名1, 口语别名2, …]   # 必填非空；与 .assistant/glossary.json 的别名联动
---
```

> ## `[ ]` N-1 AI 助手「手册通道」：用法问答自动分流（首条消息 LLM 分类 + 轻量请求形状）
>
> **性质**：新增能力。**状态**：方案已拍板（2026-09-28，P1~P3 全定），待落码。
>
> **一、定位**：软件功能多、新用户无从下手 → 内置 AI 按「手册通道」答疑软件用法：只检索官方手册（`builtin.help.search`，复用）、不深度思考、≤2-3 轮，省 token 且首字快。模式自动判定，用户无感。
>
> **二、已拍板**：① 分流 = **LLM 分类**，仅会话首条用户消息一次（复用当前模型、effort=off、无 tools、输出一个词 + few-shot 判例；失败/超时 5s 落 agent）；② 手册通道内检测操作意图 → **Toast + 自动升格**通用通道（本地词表，降格永不自动）；③ 首条消息问句+操作混杂 → 落通用通道（超集原则）；④ 手册 AI-first 重写、逐篇审核、用例即验收（工作区 `.AGENT/help-rewrite/`，脚本 `.AGENT/scripts/help-kb/verify-help-retrieval.mjs`）。
>
> **三、机制要点**：`agentSessionRepo` 会话行加 `mode: 'manual' | 'agent'`（与 `source` 并列，存量回填 agent）；`agentService` 按 mode 分叉请求形状——手册通道仅挂 `builtin.help.search`、effort 强制 off、maxRounds 2~3、不注入三层约束/感知/出题与工件规则/PARALLEL_HINT、检索结果另设小配额（总量 ≤6k 字符、默认 top2 片段 + id 深读）；术语表照常注入（口语→功能名映射直接提升检索命中）。
>
> **四、UI**：会话列表 + 对话顶部小徽标（使用帮助 / 通用助手）；回答末尾「在帮助中心打开」chip（`navigateToHelp` 深链现成）；手册通道开场快捷问题 chip（可选，三期）。
>
> **五、边界**：不新建工具；`.assistant/` 约束不注入（术语表注入）；AI 教学（source=aiTeaching）完全不适用；与支线旁问正交。
