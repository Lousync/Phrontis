# AI 教学产物声称核验（artifact claim guard）实现方案

> 2026-11-17。A 方案：回答落库前核验「已生成 / 已打开」是否有本轮产物支撑；没有则先给模型一次补救轮，仍不成立则追加系统校正文案。

## 1. 背景与取证

AI 教学里出现过「模型说示意图已生成 / 右侧工件栏已打开，但实际没有生成」的现象。取证结论不是渲染失败，而是模型本轮**根本没有调用** `visual.html`：

- `/home/lousync/生活与记录/.knowbase/agent/messages/2f24994a-ef2f-4153-a45e-e772f1a3f275.jsonl`
  2026-11-17 14:43:44 的回答声称「右侧工件栏已打开示意图『LR(0) 闭包 CLOSURE 逐步生成』」，该条 trace **工具步骤为 0**；下一条模型自认「上一条我只说了位置，没有真正调用工具」。
- `/home/lousync/生活与记录/.knowbase/agent/messages/0c10accc-e738-43ee-80de-3750c786b3d3.jsonl`
  2026-11-12 18:11:09 的回答声称「右侧工件栏已经打开：`visuals/unique-paths-dp.html`」，trace 同样没有工具调用；用户回「你没有生成」，模型承认「只在对话里描述了图，没有调用工具」。

统计：该库 52 次 `visual.html` 成功调用、0 次失败调用；上述两条是「声称但未调用」。因此问题在**声称与事实之间没有核验**，不在落盘或渲染链路。

## 2. 目标 / 非目标

**目标**

- 回答落库前检测「无产物支撑的完成态声称」；
- 命中后最多跑一次补救轮：真正调用产物工具，或明确说明没生成 / 只是之前已有的图；
- 补救轮仍无法支撑时，追加一段确定性的系统校正文案，保证用户不会把假完成当成事实；
- 补救前后的正文合并落库，避免讲解内容从历史里消失。

**非目标**

- 不改写模型原文（只追加校正文案，避免误删有效讲解）；
- 不覆盖「把图片插入笔记」这类 `vault.write` 语义（`插入 / 插到` 不是产物工具声称）；
- 不扩大到统一助手 / 日程 / 情报面（产物工具只属于 AI 教学；先限制触发面，降低误报成本）。

## 3. 判定规则（`electron/lib/artifactClaimGuardPure.ts`）

零依赖纯函数，契约脚本 strip 类型后直接跑真实实现。原则：**宁可漏报，不可大面积误报**——每次误报都会白烧一轮 LLM。

1. 先剥离 Markdown 代码围栏（围栏里是示例文本，不算声称）；
2. 只认**完成态**：`已生成 / 已经打开 / 生成好了 / 画好了 / 已更新 …`；「接下来会生成」不算；
3. 产物名词必须落在完成态动词附近（±24 字），或命中「右侧 / 右栏 / 工件栏 + 已打开 + 产物路径（`visuals/*.html`、`mindmaps/*.json`、`outputs/*.png`）」；裸「图已生成 / 图已画好」另有一条窄规则（负向后顾排除「示意图 / 思维导图 / 图片」复合词）；
4. 否定句（没有 / 未能 / 无法 / 失败）、不确定句（应该 / 可能 / 似乎 / 要不要）、未来句（稍后 / 接下来）一律不算；
5. 指代已有产物的说法（上一张 / 刚才 / 之前 / 这张 / 那张）不算；
6. 本轮已经成功写入同类产物（`visual` / `mindmap` / `image`，含 `artifact.edit` 对 `.html` / `.json` 的原地修改）时不算。

## 4. 触发流程（`electron/lib/agentService.ts`）

```
本轮 LLM 返回无 tool_calls
  → 检测产声称（仅 source === 'aiTeaching'）
      ├─ 无命中 → 正常落库
      └─ 命中且尚未补救、且不是收场轮
           → 暂存本轮正文（pendingClaimPrepend）
           → convo 追加 assistant 原文 + 系统核对提示（role=user）
           → continue（最多一次）
                ├─ 模型调用产物工具成功 → 下一轮正常收尾
                └─ 仍无产物 → finalize 追加校正文案
  → finalize：合并暂存正文 + 必要时校正文案 → appendAgentMessage
```

- 收场轮（`budgetCapped`）不补救，直接校正文案，避免与强制总结争预算；
- 中断 / 截断出口只合并暂存正文、不追加校正（错误卡片已经说明状态）；
- 强制总结出口同样走 finalize；
- 补救轮提示明确「不是用户发言」，并要求只输出必要回应、不要提及核对过程。

## 5. 改动清单

| 文件 | 改动 |
|---|---|
| `electron/lib/artifactClaimGuardPure.ts` | 新增：检测、补救提示、校正文案、正文合并（零依赖） |
| `electron/lib/agentService.ts` | 接出：产物种类记账、无工具轮核验、一次补救轮、finalize 合并 / 校正 |
| `.AGENT/scripts/ai-teaching/verify-artifact-claim-guard.mjs` | 新增契约：真实会话正例 + 否定 / 未来 / 指代 / 围栏负例 + 接线静态锁 |

## 6. 取舍与风险

- **误报成本 = 一轮 LLM 调用**。因此判定刻意偏保守，且补救提示允许「这是之前已有的图，不要重画」；
- **不改原文**：校正文案是追加的，用户仍能看到模型原话与系统结论的差异；
- **补救轮可能换模型措辞**：合并采用「首 60 字指纹去重」，模型重写讲解时不会重复两遍；
- **side lane**：写工具被硬过滤的场景下，补救轮会引导模型直接说明「本对话不能生成产物」，比空口声称更好；更彻底的提示词修正属于 B/C 方案，不在本次范围。

## 7. 验收

```bash
node .AGENT/scripts/ai-teaching/verify-artifact-claim-guard.mjs
npx tsc --noEmit -p tsconfig.node.json
npx tsc --noEmit -p tsconfig.web.json
```

契约覆盖：真实两条会话原文命中、同轮已有产物不命中、否定 / 未来 / 不确定 / 指代旧图 / 代码围栏不命中、提示与校正文案字段、正文合并去重、agentService 接线静态锁。

**实证回归（2026-11-17，本机开发库一次性扫描）**：680 条 AI 教学 assistant 消息中，以「本轮成功工具步骤」为产物事实，判定命中 **2 条** —— 正是上面两次已确认的假完成，无其他误报。
