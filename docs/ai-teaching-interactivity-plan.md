## 一、根因诊断（为什么像「传统问答」）

1. **系统提示词里没有「教师」。** 教学注入基座是通用助手人设（`electron/lib/agentService.ts` `SYSTEM_PROMPT_BASE`「你是 Phrontis 内置 AI 助手」），quiz/plan/ask 三段规则（L675-683）只定义输出格式协议，不定义教学行为——AI 默认有问必答、一次答全，天然就是问答模式。现有四类互动卡（quiz 答题 / ask 提问卡 / profile 建议 / 支线追问）全是「AI 发起 → 用户应答」。
2. **流程推进靠 AI 自觉。** 「跟我学」模板 rule 写了「每步停下让学生提问」，但 plan 围栏只是展示层，AI 常一口气讲完一大段才停。
3. **用户侧发起通道只有打字。** 划词「问 AI」也只是把选区填进输入框（`src/modules/ai-teaching/index.tsx` L704 起），没有教学意图动词。

## 二、分批计划

### 第一批：教法选择 + 快捷意图 chip（3.5.0 主体，低成本闭环）

**1. 准备态选教法（已拍板）**

- 内容：会话准备态（现选模板处）增加正交的「教法」选择，三档：
  - **引导式**（默认待 D1 拍板）：苏格拉底式——先抛问题让学生试答，卡住给提示而非答案；讲完一个新概念必须就地出一张单选快检卡（走现成 ask 围栏单选卡渲染，界面零改动）；答错给纠偏追问，不直接给答案。
  - **直答式**：维持现状行为，不出卡不追问。
  - **费曼式**：AI 出开放思考题 → 学生用自己的话打字作答 → AI 点评纠偏补漏（纯提示词实现，不做专门作答界面，见第三批 D6）。
- 落点与架构要点：
  - 教法 = 播种进会话 `CONSTRAINTS.md` 的一段行为约束（含微检验频率约束：一条回答最多一张、仅新概念才出）。**复用现有注入链路**（`resolveConstraintsForInjection` 每轮重读），`agentService.ts` 预计零改动或仅微调——这是本方案的核心取舍：不新造机制，教法就是一段约束文本。
  - UI/播种：`src/modules/ai-teaching/index.tsx` 准备态（`TEMPLATES` L184 一带）加教法选择控件 + 播种时与模板 rule 叠加写入 `CONSTRAINTS.md`。
  - 「跟我学」类流程模板的**步进节奏**（步末强制出「继续/没懂/继续讲」ask 卡）合并进同一套教法提示词，不单独成项；AI 不守协议的兜底后置（先例：quiz 解析失败占位卡 + `retryQuiz` 一键重出）。
- 验收：三种教法各开一个会话，引导式讲完概念必出快检卡、答错有追问；直答式与现状一致；费曼式出开放题且点评有效。教法写入 CONSTRAINTS.md 可在编辑器手改并即时生效。
- 成本：低（UI 选择控件 + 提示词文案 + 播种逻辑；无数据层改动）。

**2. 快捷意图 chip**

- 内容：输入框上方常驻「继续 / 考我一道 / 换个例子 / 为什么」快捷按钮，一键发送；ask 提问卡出现时隐藏（避免抢应答焦点）。文案集待 D4 拍板。
- 落点：`src/modules/ai-teaching/index.tsx` 输入区上方；发送走现有链路（纯 UI）。
- 验收：点 chip 即发送对应消息；ask 卡在场时 chip 不出现；动效走 `docs/ui-animation-plan.md` 令牌。
- 成本：低。

### 第二批：划词动词条（3.5.0 主体，体验招牌项）

- 内容：中栏选中 AI 回复任意文字 → 划词浮条追加四个教学意图动词「更简单点 / 举个例子 / 展开这一步 / 我没懂」，点动词＝带选区片段与意图前缀直接发送（区别于「问 AI」的仅引用不发送）。
- 落点三处：
  - `src/lib/assistantContext.ts`：划词接口加**可选** `verbs` 字段——不传则浮条维持现状，保证 AI 助手三形态（悬浮/右栏/整页）共用浮条不受影响；
  - 划词浮条渲染组件（AI 助手侧共用，具体文件实施时定位）：按 verbs 渲染动词区；
  - `src/modules/ai-teaching/index.tsx` L704 划词接管注册处：传入教学动词集与「点击即发送」行为。
- 验收：AI 教学中划词出现动词区、点击带上下文发送；AI 助手侧划词浮条无变化；支持 Esc/点外关闭。
- 成本：中（浮条定位边界情况 + 意图提示词拼接格式设计）。

### 第三批：深度改造（候选，视前两批反馈与排期决定，见 D5/D6）

**3. 工件回传**（沿用 8 档原型 ③ 档方向，跨学科适用性分析见 §三）

- 内容：`visual.html` 交互工件（现仅 AI 教学会话可用，`electron/lib/builtinTools.ts`）里的用户操作回传为对话输入，形成「玩 → 反馈 → 讲」闭环。现状宿主只认 height/ready/error/zoom 几个消息键，业务操作全部被丢弃。
- 落点：`electron/lib/kbVisualProtocol.ts`（消息协议扩展为**通用事件**，见 §三-3）· `src/modules/ai-teaching/ArtHtmlView.tsx`（监听转发）· `src/modules/ai-teaching/htmlShell.ts`（外壳桥接与 CSP 核实）· `visual.html` 工具 description（教 AI 生成带回传事件的工件 + 消费回传上下文）。
- 成本：高（协议 + 外壳 + 提示词三层），故不入第一批。

**4. 结构化开放作答卡（freeform 协议）**

- 内容：费曼式教法若验证高频使用，再做专门作答界面与评分流（新围栏协议 + 作答卡 UI，参考 quiz 围栏协议成熟度）。视 D6 决定。

## 三、工件回传的跨学科适用性（回应「只举了数据结构」的疑问）

工件回传的收益面**不限于数据结构**；按知识点性质分四种工件形态，各学科对号入座：

| 工件形态 | 交互方式 | 典型学科与知识点 |
|---|---|---|
| 步进器型 | 下一步 / 重置 / 自动播放 | 数据结构（排序、树堆图）；**计网**（三次握手时序、滑动窗口推进）；**操作系统**（调度甘特图逐步、页面置换 LRU/FIFO 逐访问、银行家算法安全性检测） |
| 滑块参数型 | 拖参数看曲线变化 | **高数**（拖点看切线斜率＝导数、黎曼和分割数 n 与逼近误差、泰勒展开阶数）；**线代**（拖向量看矩阵变换的像、特征向量方向与伸缩） |
| 状态机 / 拓扑型 | 点状态/边高亮演进 | 计网（TCP 状态机、路由收敛）；OS（死锁资源分配图） |
| 作答型 | 工件内做题、拖拽分类 | 各科练习（依赖回传 + 判分，成本最高，后置） |

结论：**高数/线代这类「参数敏感」学科恰是滑块型工件的最佳场景，计网/OS 是步进型主场**——冒泡排序只是步进型的代表例，不是本方案的适用边界。真正的边界是**记忆类与纯概念阅读类**知识（单词、史实、法条、定义定理本身），做不出有意义的交互工件，这些场景靠教法层（第一批）覆盖。

协议与质量要点：

1. **协议按通用事件设计**（一次开发全学科受益）：工件内任意交互统一 postMessage `{type:'kb-artifact-event', event:{kind,label,detail}}`，宿主白名单只校验结构不校验学科，转成「[工件回传] 用户把黎曼和分割数拖到 50，当前近似误差 0.02」这类可读输入进对话——不在协议里为每种学科定义专用键。
2. **生成质量风险（诚实版）**：函数图像若需数值计算（数值积分、方程求根），AI 生成的 JS 数学代码可能出错，复杂 3D 场景效果打折；公式渲染依赖 KaTeX，`htmlShell.ts` 的 CSP 是否放行需实施前核实（待办）。工件可重生成（quiz 占位卡「重出新题」同款兜底思路）。
3. 教学法上回传的增益点：AI 能看到学生在工件里「玩到了哪一步、卡在哪」，把讲解接在真实操作之后——这是滑块型场景（高数线代）里比选择题快检更强的理解检验。
