# UI 交互模式规范 —— 中央模态弹窗的限制

> **状态**：常驻规范（2026-10-04 立）· 维护口径同 `help-disclosure-pattern.md`
> **来源**：终端模块原型评审（2026-10-04）中，用户明确表达对「中央弹窗做常规确认」的反感，上升为全应用约束。
> AGENTS.md 铁律 25 是本规范的规则位；本文是模式清单与判定的展开。

## 规则本体

**中央模态弹窗（居中遮罩对话框，含一切「打断流」的同类变体）只允许用于「严重 / 不可逆 / 高危」警告。** 其余一切需要用户确认、选择、输入、知晓的场景，一律行内化完成。

判定标准：

- ✅ **可以弹窗**（且应配红色警示样式、写清后果）：
  - 不可逆删除（清空回收站、删除整个空间 / 仓库级数据）；
  - AI 发起的高危操作（删除类命令、越出仓库写盘等）；
  - 安全敏感操作的结果告知（密码库连续解锁失败一类）。
- ❌ **不得弹窗**：
  - 普通操作的二次确认；
  - AI 常规执行确认（跑个只读/常规命令还要弹窗 = 打断流）；
  - 设置、表单、多步输入；
  - 信息说明、帮助引导（那套走 `help-disclosure-pattern.md`）；
  - 成功 / 失败反馈（走 Toast）。

## 替代模式清单

| 场景 | 用什么 | 要点 |
|---|---|---|
| AI 工具 / 命令执行确认 | **行内确认卡**：出现在请求留痕处（如终端「AI 执行记录」签页），卡片上直接 [允许] [拒绝] | 不抢焦点；请求到达时用角标脉动 + Toast 提示，用户主动过去处理 |
| 后台事件需要用户注意 | 状态栏指示 + Tab / 会话签角标脉动 | 用户决定何时处理，绝不自动切视图 |
| 设置 / 表单 / 多步操作 | 右缘滑出抽屉，或页面内嵌面板 | 抽屉用 transform 过渡，遵循 `ui-animation-plan.md` 令牌 |
| 结果反馈 | Toast `showToast({ type, message, detail? })` | `alert()` / `confirm()` 本就是禁项 |
| 危险按钮防误触 | 二次点击确认（按钮态切「再点一次确认」，数秒无操作回退） | 适合删除单条笔记这类低危害但需意图的操作 |

弹层动效一律走 `docs/ui-animation-plan.md` 既有令牌（`.kb-overlay` 等），不另造过渡。

## 与既有文档的关系

- `help-disclosure-pattern.md` 管「说明文字怎么收敛」，本文管「确认与打断怎么收敛」，互补。
- **存量模态不强制回改**；新代码与改到的旧代码一律遵守（口径同脚本 emoji 规则）。
- 新增交互拿不准算不算「严重」时，默认不行内化不行弹窗二选一里**选行内**，并在评审时提出。
