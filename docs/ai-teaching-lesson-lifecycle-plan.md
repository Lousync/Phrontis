## 一、最终模型

### 1.1 层级
```
工作区（课程）
├─ 课程.md                  ← 大纲真相源（章 → 知识点）
├─ SOURCES/                 ← 课程级素材（教材/考纲/课件）
├─ {章号}·{知识点}/           ← 知识点落盘；章不落盘，用名前缀标识所属章（方案 A）
│   ├─ PROFILE.md           ← 知识点级画像
│   ├─ SOURCES.md(+原件/提取稿) ← 知识点级素材（跨该点多节课共用）
│   ├─ 总结·{知识点}.md       ← 收尾生成（知识点结束后）
│   ├─ 课时1·精讲/ { 讲义.md · 交接.md · 产物… }
│   └─ 课时2·习题/ …
└─ 自由对话/                 ← 不绑知识点的会话（不戴章前缀）
```

### 1.2 知识点生命周期（状态机）
```
未开始
 └─ 学习中：课时 1..N（线性；一节结束才能接下一节）
      · 每节结束 → AI 生成 本节讲义 + 交接.md（固定四段）
 └─ 收尾：课时都结束后出现「结束本知识点」
      · 测验（判分 → 掌握度）+ 生成 总结·{知识点}.md
 └─ 已结束：总结篇定稿 → 进入引用网络（可被跳转）
 └─（回炉）日后发现没掌握 → 状态回「待复习」，可再开课时；总结篇保留
```

### 1.3 课时生命周期
```
打开知识点 → 无课时=建「课时1」｜进行中=续上｜已结束=建「下一节」
  → 上课（本课时只读解除）
  → 用户点【结束课时】→ 本节冻结（只读）→ AI 异步生成 讲义 + 交接.md
  → 下次打开知识点 = 自动接下一节（新节开头注入上节「交接.md」）
```

## 二、数据模型

### 2.1 `progress.json`（`.knowbase/modules/aiTeaching/progress.json`）
```jsonc
{
  "v": 1,
  "workspaces": {
    "<wsId>": {
      "enabled": true,
      "units": {
        "<unitId>": {
          "status": "todo|learning|check|mastered|review",
          "mastery": 0.0,
          "lastCheckedAt": null,
          "finished": false,          // 新增：知识点是否已收尾
          "summaryRel": "AI教学/408/2·调度算法/总结·调度算法.md" // 新增：总结篇路径
        }
      },
      "lessons": {                    // 新增：由旧 sessions 升级
        "<sessionId>": { "unitId": "u2", "order": 1, "kind": "精讲", "status": "open|ended" }
      }
    }
  }
}
```
- 迁移：旧 `sessions: {id→unitId}` → `lessons: {id→{unitId, order, kind, status}}`（旧值默认 order 按时间、kind 精讲、status 视有无消息）。
- 门禁：同一 `unitId` 下，`lesson[i+1]` 可开 ⇔ `lesson[i].status === 'ended'`。

### 2.2 `课程.md`（大纲，唯一真相源，不变更语义）
仍为「章 → 知识点」两级；**章号取其在文档中的序号**，用于文件夹前缀。

### 2.3 `交接.md`（课时夹内，固定四段）
```markdown
# 交接 · 课时1 精讲
- 本节要点：…
- 掌握情况：…（哪里会了、哪里卡）
- 遗留问题：…（没讲完/没搞懂的）
- 下节建议：…（从哪继续、练什么）
```

## 三、交互规格

1. **打开即续课**：点大纲里的知识点（或中栏）→ 三态分流（§1.3）。没有「新建课时」按钮。
2. **结束课时**：上课界面按钮。点击 → 本节立即 `ended`、界面转只读 → AI 异步生成 `讲义.md` + `交接.md`（生成中显示进度，失败不阻塞结束）。
3. **上节交接**：进入某课时时，顶部显示可折叠「上节交接」条（内容 = 上一节 `交接.md`），同时注入 system。
4. **结束知识点**：课时都结束后出现按钮；用户可主动点，或 AI 在课时结束/测验达标时用 `ask` 卡轻提议一次（不唠叨）。收尾 = 出测验 → 判分 → 生成 `总结篇`。
5. **引用 / 跳转网络**：
   - **索引**：`progress.units[].summaryRel` + `finished`。
   - **注入**：每轮向 AI 注入「已完成知识点目录」（id/标题/一句话），或提供查询工具。
   - **协议**：约定 AI 输出跳转的格式（新围栏，如 ```` ```ref ```` {unitId} / 标题），渲染层解析成**跳转 chip**（点击 → `kb-open-note` 打开总结篇）。
   - **触发**：主动（用户说「想回顾 X」）/ 被动（AI 判定「完全不会 X」且 X 已结束）。

## 四、素材 / 画像 / 约束 的变化

| 项 | 现状 | 改为 |
|---|---|---|
| 素材 SOURCES | 工作区主库 + 对话级 `SOURCES/{对话}/` | **课程级**（工作区 `SOURCES/`）+ **知识点级**（`{章号}·{知识点}/SOURCES.md`）；课时不单立、懒创建 |
| 画像 PROFILE | 全局 / 工作区 / **会话** | 全局 / **课程(工作区)** / **知识点**（取消会话层）；建议卡落点＝本知识点；旧会话层懒迁移 |
| 约束 CONSTRAINTS | 全局 / 工作区 / 会话 三层 | 不变（会话层即"本课时"约束，语义不变） |
| 注入链 | 全局+工作区+会话画像、三层约束、素材目录、课程上下文 | 追加：**上节交接** + **已完成知识点目录**；画像第 3 层改知识点 |

## 五、迁移与兼容

- **目录**：旧平铺 `{工作区}/{MM-DD 课·名}/` → 新 `{工作区}/{章号}·{知识点}/{课时N·类型}/`。策略：**惰性迁移**（下次打开该知识点/课时时才挪）；无法归属的旧会话留在原处（不展示或归「自由对话」）。
- **`progress.json`**：加载时把旧 `sessions` 形状升级为 `lessons`；写回新形状。
- **画像会话层**：读时兼容（旧会话夹 PROFILE.md），新写入落知识点层。
- **素材对话级**：读时兼容，新登记落知识点层。
- **裸文件名稳定键**：`{章号}·{知识点名}` 随章名/章序变化会**重命名文件夹（含子树）**——仅在用户显式改章名/调章顺序时触发，平时不动。

## 六、分阶段实施（草案）

- **L0 数据与迁移**：`progress.json` 形状升级（units.finished/summaryRel + lessons）；旧 sessions 兼容；契约脚本。
- **L1 目录物理分层**：`{章号}·{知识点}/{课时N·类型}/` 建夹/改名/懒创建；资源管理器随之下钻；旧平铺兼容。
- **L2 课时续接与结束**：打开即续课三态；「结束课时」+ 异步生成 讲义/交接；本课时只读 + 上节交接过。
- **L3 知识点收尾**：测验 + `总结篇`；用户/AI 混合触发。
- **L4 引用网络**：已完成目录注入 + 跳转协议 + 跳转 chip（主动/被动）。
- **L5 素材/画像改层**：SOURCES 知识点级、PROFILE 知识点层；迁移与建议卡落点。

依赖：L0 → L1 → L2 → L3 → L4；L5 独立。

## 七、验收门禁（实施时）
- 双 tsconfig 零新增；L0/L1/L2 补独立契约脚本（progress 形状升级、目录建/改名、课时三态判定——纯函数）；
- 真机：开知识点自动续课、结束课时生成讲义/交接、知识点收尾出总结、跨对话跳转 chip 可点开；
- 收尾提醒同步 `resources/help/` AI 教学相关篇目。
