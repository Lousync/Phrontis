## 二、会话 ⇄ 编辑区文件夹绑定（本轮核心设计）

### 2.1 目标行为

**新建一个对话 ⇄ 在编辑区（Vault 文件树）同步创建一个专属文件夹**，该对话的一切产物落在这里：

```
Vault 根/
└─ AI教学/                        ← 模块根目录，名称可在设置中改（aiTeachRootDir，已拍板 2-1）
   └─ 2026-09-06 我的教学对话/     ← 每个会话一个文件夹
      ├─ CONSTRAINTS.md           ← 本会话约束（§2.3）
      ├─ .session.json            ← 会话锚点（已拍板 2-3）
      └─ (AI 生成的讲义.md / 大纲.md / PPT 素材引用 …)
```

### 2.2 设计要点（待逐项确认）

| # | 事项 | 结论/建议 |
|---|---|---|
| 1 | 文件夹命名 | `{MM-DD} {会话标题/首条消息前N字}`，重命名会话 = 重命名文件夹；非法字符清洗 |
| 2 | 创建时机 | 新建对话（含「新建任务」模板）确认创建时即建文件夹；**空会话不删文件夹（已拍板 2-2）** |
| 3 | 产物落盘 | AI 生成文档（讲义/大纲/笔记）与「整理成文档」产物写入该文件夹（§3.8-2）；已有「改动清单可跳编辑器」链路改为默认定位到此文件夹 |
| 4 | 知识库模块可见性 | 遵循读写分工约定：无 frontmatter id 的文件是草稿，知识库不显示 → 文件夹内容天然不污染知识库，直到用户在编辑器里正式保存 |
| 5 | 会话数据的存储 | 对话记录本身（消息流）不动——仍走现有存储；**文件夹只放产物文件** + `.session.json` 锚点（已拍板 2-3） |
| 6 | 删除联动 | 删除会话时文件夹处理做成**设置项**（ask/keep/delete，已拍板 2-4） |
| 7 | 存量会话 | 已有会话没有文件夹：**懒创建（已拍板 2-5）**——下次真正产生文件时才补建 |
| 8 | 多仓库 | 文件夹建在「当前激活仓库」；会话切换仓库后产物跟随激活仓库（与 vault 约定一致），文档需写明该边界 |

### 2.3 会话要求 → CONSTRAINTS.md（2026-09-06 拍板方向）

「会话要求」从数据库字段（现状 `agent:setSessionInstructions`，见 §3.3）升级为**会话文件夹内的一个 md 文档**，专名 `CONSTRAINTS.md`：

- AI 在本会话内自动读取并遵循其中的约束（进会话/发消息时作为 system 上下文注入，文件是唯一真相源）；
- 用户可直接在编辑器里改这个文件，改动即时对 AI 生效（激活重读约定）；
- **模板机制**：工作区层级可创建 CONSTRAINTS 模板（如 `AI教学/{工作区}/_templates/CONSTRAINTS.md`），新建对话时自动复制一份到会话文件夹，会话内再各自修改；
- 文件示例：

```
AI教学/数学冲刺/
├─ _templates/
│  └─ CONSTRAINTS.md          ← 工作区模板：新建对话时复制
└─ 09-06 随堂测验/
   ├─ CONSTRAINTS.md          ← 本会话约束：如「只用中文」「先结论后理由」「只考第 3 章」
   ├─ 讲义.md
   └─ (产物…)
```

待拍板：旧 DB 的 sessionInstructions 字段是否保留兼容（建议：读时兼容、写只写文件，一个版本后迁移完退役）；CONSTRAINTS.md 是否在工作区卡片/会话页签上给「有约束」标记。

## 三、布局改版（方向性结论，细节待原型拍板）

### 3.1 已明确的方向（用户原话归纳）

1. **每个对话单独拥有一个完整界面**——顶部「会话页签」就是会话切换器（类似浏览器 Tab / 编辑器文件 Tab）；
2. 因此**左栏的「会话」列表区块移除**（不再需要侧边会话管理）；
3. 左栏保留「任务规划」（当前会话的教学步骤流）；
4. 右栏（资料来源 / 产物 / 本次改动 / 剖析当前会话）保留，归属当前会话；
5. 顶部工具组（会话要求 / 时间线 / 文档地图 / 禅模式）保留，归属当前会话。

### 3.2 第二轮补充方向（2026-09-06）

**PDF/PPT 读取优化（回应「PDF 过大 / 图表公式识别差」两点顾虑）**：

1. **页面区间读取**：登记素材时可标注页码/页区间（如「课件.pptx 第 12-34 页」）；AI 读取时只提取区间内容，整本大文件不再灌进上下文。项目已有 pdfjs-dist（PDF 工具箱在用），PDF 文本按页提取是现成能力；PPTX 用 JSZip 解 XML 取每页文字。
2. **提取稿缓存**：首次按区间提取后，把文本落成 `_extracts/` 下的 md 提取稿；之后 AI 一律读提取稿，不再重复解析原文件——快且省 token。
3. **图表/公式识别优化**（分两层，控制成本）：
   - **默认走文字层**：PDF/PPT 的文本层直接可取，纯文字内容零成本；
   - **视觉转写按需触发**：对图表/公式密集的页，把该页渲染成位图交给多模态模型，转写为「LaTeX 公式 + 图表结构化描述（表格转 md 表格、图生成说明）」，结果并入提取稿。触发方式见新决策点 3-21。

### 3.8 第四轮：时间线快速定位 / 整理成文档 / 去气泡化（2026-09-06）

**1. 时间线 → 对话区右缘「快速定位条」**（参照 WorkBuddy 的回答导航条形态，用户截图）：

- 对话流右缘一条窄竖条：每个回答/消息对应一个刻度点，hover 时浮出该条消息的预览，点击即滚动定位到该消息；

**2. 「文档视图」改造为逐条「整理成文档」**：

- 顶栏「文档地图/文档视图」按钮移除；改为**每条 AI 回答下方一个「整理成文档」按钮**；
- 点击后 AI 把该条回答整理成结构化 md 文档，**自动写入当前工作区目录**（建议落会话文件夹，如 `AI教学/{工作区}/{会话}/讲义·xxx.md`）；

**3. AI 回复去气泡化**（参照 WorkBuddy 回答样式）：

- 用户消息保留气泡/右对齐（区分发言者）；
- **AI 回复去掉气泡框**：平铺渲染——markdown 直接铺在版面上（标题/列表/代码块/表格原生样式），下方一条轻量操作条（整理成文档 / 复制 / 轨迹折叠展开）；
- 好处：长讲义、代码块、表格的阅读体验大幅提升，与「整理成文档」的产物形态一致（对话里看到的 ≈ 最终文档的样子）。
