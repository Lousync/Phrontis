## [~] N-1 顶栏状态区：番茄钟进度

> **2026-11-05 暂存**：用户转向 N-2（顶栏昼夜主题），本项先保留原型与讨论记录，不继续落码；N-1 与 N-2 是**前景状态层**与**背景氛围层**的关系，后续可叠加。

### 1. 用户原话与截图

> 如图的这个窗口状态栏太空了我想添加点东西，比如如果开启了番茄钟就有个进度条之类的。

截图对应的是 **顶部 `TitleBar`**：左侧 macOS 红绿灯 + 置顶按钮，右侧整段空白。不是底部的工作台状态栏（`WorkbenchStatusBar`）。

**关键结论**

1. 用户说的是**全局顶栏**，不是工作台底部状态栏；顶栏除禅模式 Z2 外一直存在，适合做「全局状态」。
2. 顶栏当前拿不到番茄钟状态，根因是 Provider 的作用域；这是落码前必须解决的结构问题。
3. 数据层不需要新增字段；`visible / phase / running / done / progress / display` 已经够用。
4. 现有底栏、右栏、popout 都有番茄钟指示，顶栏加入后要统一「哪一层显示什么」，避免四处重复。

### 3. 需求拆解（初稿，待确认）

- **目标**：让顶栏在空白时有轻量、可扫读的全局状态；第一项是番茄钟，不是重做番茄钟面板。
- **显示条件**：番茄钟被激活（`visible === true`）后出现；空闲不占位。运行 / 暂停 / 完成三态要有区分。
- **信息层级**：阶段（专注 / 休息）> 剩余时间 > 进度；预设、开始/暂停等控制不放进顶栏（v1）。
- **位置**：优先右侧或顶栏底边，避开左侧窗控、DEV 角标、更新入口、置顶按钮；同时给未来状态项留扩展位。
- **交互**：点击状态区 → 走现有 `pomodoro:activate` 事件打开面板；悬停给 tooltip；不在顶栏做计时控制，避免误触。
- **状态源**：同窗口用 `PomodoroContext`。需要把 `<PomodoroProvider>` 上移包住 `<TitleBar />`；不建议为了顶栏另接一套 IPC 快照。
- **视觉**：沿用 `--accent`（专注）/ `--success`（休息）/ `--warning`（暂停）；进度只动 `transform` 或 `opacity`，700ms linear；补 `prefers-reduced-motion` 兜底；不另造 `transition-all`。
- **血条实现约束**：落码时不要用 `width` / `left` 驱动填充。用「固定渐变层 + 轨道色遮罩层」：渐变层铺满整条，遮罩按进度 `transform: scaleX(...)`（充能遮右侧、掉血遮右侧），这样只动合成属性，满足铁律 13。分段样式用 CSS `mask` 或 12 个段节点，落码时再评估。
- **边界**：最小窗口 900px 下不挤压左侧控件；最大化 overlay 之上可点击；禅模式 Z2 顶栏隐藏时自然不显示；DEV 角标 / 更新入口出现时布局不跳。
- **去重**：底部 `WorkbenchStatusBar` 现有番茄文字是保留、移除，还是降级为「只在底栏显示时间、顶栏只显示进度」，需要拍板。
- **扩展性**：右侧可以预留为通用「状态槽」，未来放 AI 运行中、索引中、更新可用等；本次只落番茄钟，不提前抽象过度。

### 4. 可选形态

#### A. 右对齐「专注胶囊」

`[Timer 图标] 专注 24:36`，旁边一条 40–60px 的迷你进度条或小圆环；点击打开面板。

- 优点：信息完整、可点击、和左侧窗控形成左右平衡；未来可并排扩展其他状态胶囊。
- 缺点：中间仍会空；胶囊本身需要 `no-drag` 与 `z-10`；文字会和底栏重复。

#### B. 顶栏底边「通栏进度线」+ 右侧轻量时间

顶栏最底边一条 2px 全宽进度线（`scaleX(progress)`），右侧只放 `专注 24:36` 小字；文字可点击。

- 优点：最像「进度条」，用满整条宽度，视觉上直接解决「太空」；信息密度低、不抢注意力。
- 缺点：2px 线可能偏弱；需要新增一个只动 `transform` 的进度工具类；全宽线容易被误读成加载条。

#### C. 居中「专注胶囊」

把 A 放到底栏中央。

- 优点：直接填补最显眼的中央空白。
- 缺点：和窗口拖拽区、未来可能的标题 / 命令中心冲突；窄窗口下最容易挤压；像横幅，不像状态。

#### D. A + B 组合

右侧胶囊 + 底边通栏线。

- 优点：存在感最强，信息与氛围兼顾。
- 缺点：对 36px 顶栏来说偏重，容易变成「为了填满而填满」。

#### E. 右对齐「渐变血条」

右侧一条紧凑血条：阶段文字 + 12px 高、132px 宽的圆角条 + 倒计时；条内有深色轨道、渐变填充、内阴影和顶部高光。

- 优点：信息完整、最有「血条」质感；和左侧窗控形成左右平衡；未来可扩展成通用状态胶囊。
- 缺点：中间仍会空；需要 `no-drag` 与 `z-10`；比 A 的胶囊更抢眼。

#### F. 同排「通栏渐变血条」

把血条放进 36px 顶栏行内：左侧窗控之后、右侧「阶段 + 倒计时」之前，血条垂直居中、铺满中间空白；**不放在顶栏底边**，避免看起来像顶栏和内容之间的分隔线。

- 优点：最像游戏 HP 条，直接用满空白宽度；血条与窗控、时间在同一视觉行，不会和内容区粘连。
- 缺点：视觉最抢眼；渐变和光泽要克制，否则和应用的纸感主题冲突。

**初步建议（第二轮更新）**：用户已明确偏好「有渐变色的血条」，重点从 B 的细线转向 **E / F**。E 更像一个完整的状态芯片，F 更像一条真正的血条铺满顶栏行内；先看原型再定。

第二轮补充（血条方向）：

> 用户原话：**「我喜欢那种进度条，有渐变色的血条那种。」**

原型据此新增 **E / F** 两种血条形态，并加「血条样式」开关：

第三轮修正（用户截图反馈）：

- F 的行内条现在占据窗控与时间之间的整段空白，既像血条，也不会和内容区粘在一起。

## [~] N-2 顶栏昼夜主题：随一天时间变化

### 1. 用户原话

> 先暂存着我有个新的想法，就是我想做一个这种效果，这个顶栏弄成随着一天的时间变化而变化的主题，比如早上是什么样子，中午是艳阳高照，黄昏，晚上变成月亮那种主题变化，你试着设计一下。

### 2. 目标与非目标

**目标**

- 把 36px 高的 `TitleBar` 做成一条**微型天空**：背景渐变、太阳 / 月亮位置、云 / 星星随本地时间连续变化。
- 早上柔和、正午明亮、黄昏暖橙、夜晚深蓝 + 月亮 / 星星；变化要慢、轻、不打断工作。
- 窗控、置顶、右侧时间 / 阶段文字在**所有时段**都保持可读。
- 默认只影响顶栏；可选「整窗氛围」把天色轻轻溢到内容区顶部。

**非目标（v1）**

- 不做全屏动态壁纸，不逐帧渲染整窗背景。
- 不做天气（晴 / 雨 / 雪）与地理位置，只按本地时间。
- 不替代应用主题 / 插件主题，只覆盖顶栏这一层。
- 不要求太阳 / 月亮天文精确；优先视觉连续与低干扰。

### 3. 设计草案

**时间轴 / 关键帧**

- 00:00 深夜 → 04:30 凌晨 → 05:30 黎明 → 06:30 日出 → 08:00 清晨 → 11:00 上午 → 12:30 正午 → 15:00 午后 → 17:30 黄金时刻 → 19:00 黄昏 → 20:30 夜晚 → 24:00 深夜。
- 顶栏背景用 3 段线性渐变（top / mid / low）+ 1 层跟随太阳 / 月亮的径向光晕；颜色在关键帧之间按分钟插值，不跳变。
- 右侧状态胶囊显示 `HH:MM · 阶段`，前面带一个小太阳 / 月亮图标；胶囊使用半透明底 + 背景模糊，保证在亮天空 / 夜空上都可读。

**太阳 / 月亮**

- 白天 06:00–19:00：太阳沿顶栏中部从左到右走一条低弧线，正午最高。
- 夜晚 19:00–06:00：月亮从右到左走同一条弧线；19:00 与 06:00 两个交接点位置连续，避免“月亮突然跳走”。
- 太阳 / 月亮只占约 12px，带柔和光晕；位置用 `transform: translate()` 驱动，不用 `left/top` 做动画。
- 黄昏的太阳偏橙、正午偏白黄；夜晚的月亮偏冷白，带一点月面阴影。

**云与星星**

- 白天 2–3 朵低透明度软云，缓慢左右漂移；黎明 / 黄昏染成暖色；夜晚淡出。
- 夜晚 6–9 颗 1–2px 星星，轻微闪烁；白天淡出。
- 所有粒子 / 漂移都走 `opacity` / `transform`；`prefers-reduced-motion` 下停止漂移与闪烁，只保留静态天空。

**前景可读性**

- 根据天空亮度自动切换 `--tb-fg`：亮天空用深色文字 / 图标，黄昏与夜晚用浅色；交通灯色点不变。
- 顶栏时间胶囊始终带半透明底 + 1px 描边；置顶图标加轻微投影，避免在亮太阳 / 云上消失。
- 文字颜色切换用短过渡，避免生硬；背景渐变按分钟缓慢变化，不做逐帧跳色。

**范围**

- 默认「仅顶栏」：只改 `TitleBar`，应用主体仍保持纸感 / 深色主题。
- 可选「整窗氛围」：在内容区顶部加一层从天空色到透明的软光晕（`mix-blend-mode: soft-light`），170px 内淡出；不改变卡片可读性。
- 再往下一步才是「内容区也跟着变暗 / 换主题」，本期不做。

### 6. 落码注意（尚未实施）

- 纯函数 `skyAt(minute)` 负责「时间 → 颜色 / 天体 / 星星 / 云 / 前景色」，独立成零依赖文件，便于补契约脚本。
- 渲染层只在 `TitleBar` 内挂一个 `TitleBarSky` 子组件，避免每分钟把整个 App 重渲染；更新频率建议 60s，或对齐到下一分钟。
- 天体位置用 `transform`，尺寸变化用 `opacity`；云 / 星星动画只动 `transform` / `opacity`。遵守铁律 13。
- 顶栏是 `drag-region`：天空层 `pointer-events: none`；时间胶囊与置顶保持可点击，必要时 `no-drag`；最大化 overlay 之上仍要可点。
- `prefers-reduced-motion`：关掉云漂移、星星闪烁、天体过渡；天空颜色仍随时间更新。
- 对比度：`--tb-fg` 由天空亮度推导，不是写死；时间胶囊必须有底衬，避免黄昏 / 正午某些角度读不清。
- 设置项：建议 `titleBarDayCycle`（开关）与可能的 `titleBarDayCycleAmbient`（整窗氛围），默认值待拍板；不要硬编码。
- 性能：36px 高，背景渐变 + 1 个天体 + 3 朵云 + 9 颗星；全部 CSS，不用 canvas / 定时器逐帧重绘。每分钟一次状态更新即可。

### 7. 方向升级与原型 v2（2026-11-07）

用户体验 v1 原型后拍板，方向从「顶栏装饰」升级为**整窗昼夜动态主题**：

- **§5 待拍板问题的当次结论**：① 范围 → 不止顶栏，整窗配色随时间插值，顶栏天空是主题的一部分（原 v1 非目标「内容区跟随」被推翻）；② 密度 → 保持原型（天体 + 3 云 + 9 星）；③ 默认 → 开启；④ 用户反馈太阳质感不对，v2 已改为羽化边缘 + 三层日冕。
- **v2 原型**：同路径 `tmp/titlebar-daycycle-proto/index.html`（覆盖 v1）。核心变化：
  - 配色令牌化：整窗语义令牌（bg/card/border/t1..t3/accent/ok/warn/bad/edge/shadow…）随时间整组插值，共 12 关键帧；
  - 黎明 05:30（暖紫暮调）与暮色 19:15（plum 暮调）各为**自成体系的中间主题**（浅色文字），深浅色切换各经一次有设计感的交叉淡化，不路过脏灰区；
  - 质感手法：内容区双层环境光跟随太阳/月亮方位（Linear/Raycast）、顶栏底段向内容区背景色「融化」、Stripe 式整窗噪点纹理（feTurbulence，`mix-blend-mode: overlay`）消色带；
  - 对照模式三选：昼夜主题 / 正午定格 / 经典纸感（原静态主题）；URL 参数 `?time=HH:MM&mode=noon|paper&play=1`；
  - 落码提示两条新经验：① 首绘必须同步执行，不能放 `requestAnimationFrame`（后台节流导致首帧空白）；② 颜色插值产物是 `rgba()` 字符串，混色工具函数需同时接受 hex 与 rgba 输入。
- **影响面变化**：不再是 TitleBar 局部改造，而是接入应用主题体系（与主题插件 / 深浅色模式的关系需在技术方案阶段重新界定）。
- **落码（2026-11-07）**：`docs/daycycle-theme-plan.md`；契约抓出并修复的关键设计问题——深浅 crossover 线性插值会让文字与背景同陷中间灰（06:00 段正文对比度一度 1.1），最终方案 = 文字极性阶梯切换 + 过带压缩到 12 分钟（黎明 354/366、黄昏 1140/1152 四帧），契约脚本 A6/B2 断言锁定。
