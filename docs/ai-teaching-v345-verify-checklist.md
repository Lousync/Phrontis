## 怎么用这份清单

1. 启动：在仓库根执行 `npm run dev`（dev 端口 7173）。**启动前先清掉 `ELECTRON_RUN_AS_NODE`**：cmd 里 `set ELECTRON_RUN_AS_NODE=`，PowerShell 里 `Remove-Item Env:ELECTRON_RUN_AS_NODE`。改了 `electron/` 下的文件必须重启 dev，渲染层改动的热更新不代表主进程是新的。
2. 准备一个**测试用仓库**（不要拿日常库）：里面至少 1 个工作区、一段可讲的素材（pdf 或 md），网络条件允许时再准备一个可访问的网页地址。
3. 按 A → J 顺序过。每组先读「前置」，再逐条勾。每条给了「步骤」和「预期」，两者都成立才算通过。
4. 发现异常时只记三样：**组号 + 步骤号 + 现象**（例如「G2 第 3 点后下一轮又从头讲」），并顺手记下当时的会话名与大概时间，便于回查。
5. 全组过完后，再单独回看文末「已知不作为验收失败项」，避免把既有问题记成本轮回归。
6. 需要更硬的证据时，跑对应组的契约脚本（每条末尾的「失败先看」里给了脚本名）。脚本一律在仓库根执行：`node .AGENT/scripts/ai-teaching/<脚本名>`。

## A. 轮次导航（右缘短横列）

前置：一个已有若干轮问答的会话，中栏滚动容器里有消息；右栏保持关闭。

- [ ] **A1 只在 2 轮起显示** —— 步骤：新建会话只发 1 条消息。预期：右缘没有短横列；发第 2 条后出现。
- [ ] **A2 6 轮 = 6 条短横** —— 步骤：连发 6 条短消息（每轮一条用户提问）。预期：右缘中部竖排 6 条短横，不贯穿全高，垂直位置约在 55% 处。
- [ ] **A3 20 轮 = 11 条，当前条加宽** —— 步骤：把会话凑到 20 轮后滚到第 1 轮顶部、再滚到中间。预期：仍是 11 条（不是 20 条）；当前那条更宽且用强调色；滚动时高亮条跟着换。
- [ ] **A4 60 / 120 轮仍 11 条** —— 步骤：用长会话（或连发短消息）凑到 60 与 120 轮，分别滚到顶、中、底。预期：短横数量恒为 11，首条对应第 1 轮、末条对应最后一轮；滚到底时末条为当前。成本较高时可只跑一次 120 轮，算术部分交给 `verify-turn-rail.mjs`。
- [ ] **A5 hover 展开浮动卡片** —— 步骤：鼠标移入短横列，停 1 秒后移出到卡片外再等。预期：立即展开贴右缘的浮动卡片；移出后约 240ms 才收起（不是一离开就闪断）。
- [ ] **A6 卡片行内容** —— 步骤：在卡片里看各行。预期：每行是「该轮用户提问的首句」，右对齐、行尾一条短横，超长省略；当前轮那行用强调色；行数超过卡片高度时卡片内滚动（页面本身不滚）。
- [ ] **A7 点击跳转 + 洗色** —— 步骤：点第 2 行。预期：中栏滚到该轮（距离近时平滑、超过两屏直接跳），目标消息行闪一层淡强调色约 1.8 秒后消失，卡片自动关闭。
- [ ] **A8 键盘全流程** —— 步骤：Tab 把焦点移到短横列 → 按 `↓`/`↑`、`PageDown`/`PageUp`、`Home`/`End` → 按 `Enter` → 再聚焦后按 `Esc`。预期：方向键只移动卡片里的高亮（不立刻滚动），`Enter` 才跳到该轮并关闭，`Esc` 只关卡片、不触发模块其他 Esc 行为（不误退禅/不最小化）。
- [ ] **A9 钉住（点击短横列）** —— 步骤：单击短横列空白处，然后把鼠标移开。预期：卡片保持展开（钉住），只有点击卡片外部或按 `Esc` 才关闭；再点一次不会异常闪断。
- [ ] **A10 与右栏开合联动** —— 步骤：打开短横列让卡片展开，再用顶栏图标/Ctrl+Alt+B 打开右栏，然后关闭右栏。预期：整列（含卡片）随中栏一起左移，不被右栏盖住；关闭后回位；开合过程中卡片不闪退、不跳到面板下面。
- [ ] **A11 reduced-motion** —— 步骤：P3 关掉动画后重复 A5 / A7 / A8。预期：卡片无淡入位移（直接出现/消失），跳转瞬时完成，**不出现**洗色层。
- [ ] **A12 贴底时当前轮 = 最后一轮** —— 步骤：滚到最底部。预期：高亮的是最后一条短横（不是倒数第二条）。

**失败先看**：`.AGENT/scripts/ai-teaching/verify-turn-rail.mjs`（采样/当前轮/键盘算术）；组件 `src/modules/ai-teaching/TurnRail.tsx`；样式 `src/styles/index.css` 里 `.kb-turn-rail` / `.kb-turn-dash` / `.kb-turn-flash`；跳转与闪烁在 `src/modules/ai-teaching/index.tsx` 的 `jumpToTurn`。

## B. 右栏多页签

前置：右栏宽度先保持默认（约 480），会话已发过至少一条消息（会话夹存在，画像/要求才有文件可开）。

- [ ] **B1 同类多开** —— 步骤：`+` → 笔记两次（每次会自动新建一篇会话速记，得到两个笔记页签）；`+` → 电子书两次（得到两个书架页签），各自点开一本不同的书。预期：四个以上页签并存、可来回切；切换只换内容，页签对象不重建。
- [ ] **B2 同文件 / 同书去重** —— 步骤：连点两次「画像」pill；在书架页签点开一本书 → 返回书架 → 再点同一本。预期：前者仍只有一个「画像」页签（被聚焦而不是新建）；后者仍是同一个书页签，不出现第二本同名书。
- [ ] **B3 【P0】重启恢复** —— 步骤：开 3 个页签（例如 笔记 A / 电子书 B / 旁问），把活动页签切到第 2 个 → 完全退出应用 → `npm run dev` 重进 AI 教学。预期：3 个页签按原顺序回来，活动页签仍是第 2 个，标题与文件/书目正确。
- [ ] **B4 草稿不持久化** —— 步骤：`+` → 旁问 → 不提问，直接重启。预期：该草稿页签消失；已落库的旁问页签正常恢复。
- [ ] **B5 关闭页签的选中顺序** —— 步骤：开 3 个页签，选中间那个点 `×`；再关到只剩一个并关掉它。预期：关中间时活动页签落到右邻；关最后一个后面板不自动关，露出零态卡（「没有打开的页签」+ 用右上角 `+` 新建）。
- [ ] **B6 脏页签拦截关闭** —— 步骤：在笔记页签里改点文字（1 秒内），立刻点 `×`。预期：不静默丢正文——要么先保存再关，要么弹 Toast「这份文件还有未处理的改动」（冲突未决时）。
- [ ] **B7 文件页签冲突** —— 步骤：用编辑器打开同一个 md 并保存（改动磁盘）→ 回笔记页签继续输入并等 1 秒。预期：出现行内冲突条（不是模态），有「保留我的版本」与「重新载入」；选前者写盘、选后者丢弃本地改动并读盘。冲突未决时关这个页签应被拦住并提示。
- [ ] **B8 就地编辑保存** —— 步骤：在笔记页签输入一段，等 1 秒以上，关掉页签再重新打开同一文件。预期：内容在磁盘上（重新打开能看到）；无「草稿/未保存」概念，标题不变。
- [ ] **B9 画像/要求页签跨会话** —— 步骤：在会话 A 打开「画像」页签 → 切到会话 B → 回看该页签并编辑保存 → 打开 A 的 `PROFILE.md`。预期：页签仍在（活过会话切换），改动写回 **A** 的文件，不是 B。
- [ ] **B10 旁问历史入口** —— 步骤：`+` → 旁问（打开二级浮层）。预期：顶部「问整段对话」，下面是跨对话的旁问列表（标题、来源对话、时间、未读点）；点已有条目=新建或聚焦对应页签，`Esc` 返回 `+` 菜单而不是直接关面板。
- [ ] **B11 旁问草稿 → 正式** —— 步骤：在某条 AI 回答上点追问（锚定）→ 右栏出现「新旁问 · 第 N 条」→ 发第一问。预期：发问前不写库、不进历史、重启即丢；发问后标题变成首问截断、进入历史列表、页签持久化。
- [ ] **B12 宽度与窄头部** —— 步骤：拖左缘把手把右栏拖到约 420，再拖到最小。预期：≥400 是单行页签条；<400 收成「当前页签名 + ⌄」的窄头部；最小宽约 360（拖不到 320，方案里写的 320 不可达）。
- [ ] **B13 溢出下拉** —— 步骤：开 4 个以上长标题页签，把宽度收到 400 上下。预期：页签条右缘渐隐并出现 `⌄`（全部页签），点开是竖排全量列表（含关闭按钮）；窄头部同样能打开这个列表。
- [ ] **B14 零页签空态** —— 步骤：关掉所有页签。预期：零态卡居中、文案指向右上角 `+`；头部 `+` 仍可用，`×` 关闭面板。

## D. 顶栏与网页页签

- [ ] **D1 顶栏只剩一枚图标** —— 步骤：看中栏顶栏右侧。预期：只有一枚「打开右侧栏」图标；结课组、画像、工件 chip、会话要求、进度、收尾都**不在**顶栏。
- [ ] **D2 右栏打开时图标消失** —— 步骤：点该图标打开右栏；再关掉右栏；再用 `Ctrl+Alt+B`。预期：右栏打开时图标不渲染（不是置灰）；关闭后图标回来；快捷键两态都生效。
- [ ] **D3 网页页签单页化** —— 步骤：打开网页页签。预期：顶部只有一行「← → ↻ [地址栏] ↗」，**没有**内层 w1/w2/w3 页签条，也没有内层 `+` / `×`。
- [ ] **D4 空态点阵** —— 步骤：新建网页页签（无地址）。预期：内容区是极淡的 18px 点阵底纹；地址栏仍在原位、占位符「输入网址」；前后退/刷新/外部打开按钮是 disabled 而不是消失（地址栏不跳位）。
- [ ] **D5 打开一个真实页面** —— 步骤：地址栏输入一个可访问的 https 地址并回车。预期：原生视图加载页面，顶部出现 2px 加载进度条；页签标题更新为页面标题；后退/前进/刷新可用。

## 已知不作为验收失败项

- **`verify-scope-files.mjs` 报 ENOENT**：既有脚本的环境问题（它会把三个模块的 import 机械改写成桩模块，再用 temp 目录往返），与本轮改动无关；只看其余断言是否 PASS。
- **url 抓取在无网络 / 目标站点不可达时无法验证**：D7、D8、H4、H5 需要真实可访问的网页；离线时只验「探测失败有错误提示、不卡死在进度条」。
- **网页多开**：本轮**有意只允许一个网页页签**（再开复用当前页签并导航）。不要把它记成「+ 新建网页没反应」。
- **工件入口**：顶栏工件 chip 已退役，入口改为右侧 12px 贴边条；「从顶栏点开工件」是旧行为，不作为回归项。
- **题单 strict 下答案全 B 未报错**：这是设计（自动均衡 + 只退回一次），见 I1；只有结构非法与长度暗示才拦。
- **台账正文 / 错题块不可视**：它们只进模型上下文，界面不展示；只能按 G 组的**行为**判断，或查 `progress.json` / `records.json` 的程序侧数据。
- **面板最窄 360**：方案里提到的 320、420 两个宽度只有 420 可达；320 会被夹到 360，不算缺陷。
- **「轮次标题」不是 AI 回答的首行**：导航刻度是**用户提问**（第 N 轮 = 第 N 条用户消息）；只发图片的那一轮标题是「第 N 轮（图片）」，不是空行 —— 属设计。
- **待确认项**：仓库内没有给「本轮注入内容」的调试面板，若需要逐字核对注入文本，只能临时加日志（本轮未提供入口）。
