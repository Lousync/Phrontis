## F-1 发音方案不可接受（2026-11-03）

**反馈**：当前原型的发音方案很不好。

**确认**：原型使用浏览器 `speechSynthesis`，与现有 `src/lib/tts.ts` 是同一套系统 TTS。如果最终选定「系统 TTS」，落地后的音色/音质基本就是现在这个效果（取决于操作系统语音，Windows 为 SAPI，Linux 为 speech-dispatcher / espeak）。因此不能按「系统 TTS」定稿。

**影响**：
- 背单词的发音是高频操作，音质差会直接影响体验。
- 原 qwerty-learner 的单词发音走在线有道音频，本地并没有词音资源。
- 若换本地神经 TTS，会增加安装包体积与跨平台打包复杂度；若走在线，会破坏「数据 100% 本地」。

**待定选项**：
1. 本地神经 TTS（Piper / Kokoro / sherpa-onnx 等）：离线、音质明显好于系统 TTS，预计增加 50–150MB，需处理 Windows / Linux 二进制与语音模型。
2. 在线 TTS（有道 / Edge TTS 等）：音质最好、实现最轻，但联网且会把单词发到外部服务。
3. 预生成音频包：按词库生成并随包/按需下载，播放最稳，但体积大、维护成本高。
4. 混合：本地神经 TTS 为主，系统 TTS 仅在无可用模型时兜底；在线作为显式可选项。

**当前建议**：优先评估本地神经 TTS，系统 TTS 只做兜底；等用户把问题列完后一起定。
