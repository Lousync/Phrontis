# v3.9.0 体验反馈台账

> **用途**：本文件是 v3.9.0 这一版的体验反馈**唯一归集处** —— 开发负责人自用发现的、以及其他用户反馈的问题都记到这里；每条记「现象 → 定位 / 根因 → 处置方向」，攒够一批再统一开修。
>
> **被测构建**：`packs/3.9.0`（2026-10-16 打包，`package.json` = `3.9.0`），源码 = `main` @ `d046884`；工作分支 = `v3.9.1`（基点即 `main`）。
> **发布状态**：**尚未对外发布** —— GitHub Releases 最新仍是 `v3.4.1`（3.5.0 起都只做了本地测试包，未 publish）。所以本版没有「正式版上线后」的时序含义，纯粹是测试包反馈。
>
> **★ 记录纪律（本文件的第一原则）**：**只记录，拍板前不动码**。登记时把「现象 → 定位 / 根因 → 处置方向」写清即可，**不要顺手改代码**；等开发负责人说「修」再动手（见 `AGENTS.md`「开发流程」第 3 条）。
>
> **★ 先判「是不是有意设计」**：有一部分行为是按方案主动做的（先例见 `docs/v3.4.0-feedback.md` 的 `F-1`）。这类先标 `[-]` 并给出方案依据，等拍板「确实要改」再转 `[ ]` —— 别把设计决策当 bug 修回去。
>
> **与其他文档的分界**：
> - `docs/pending-fixes.md`（`B-n`）：**通用**待修 bug 台账。本文件只收 v3.9.0 的体验反馈 / 落差；某条若确认与版本改版无关，转登记进那边并从本表移除。
> - `CHANGELOG.md`：面向用户、只写已交付功能。本文件是**开发侧**的待办输入。
> - `docs/v3.4.0-feedback.md` / `docs/v3.5.0-feedback.md`：各自版本的台账，**编号互不相通**。本文件编号从 `F-1` / `N-1` 重新起。
>
> **编号与状态**：`F-n`（Feedback，缺陷 / 落差）与 `N-n`（New，功能需求）**同文档、不同区段，各自从 1 起**，全局递增不复用。
> 状态标记：`[ ]` 待办 / `[~]` 处理中 / `[x]` 已修 / `[-]` 不修（有意设计，保留说明）/ **`[?]` 观察中**（现象无法稳定复现，先挂着等复发；复发即转 `[ ]` 并把复现信息补进该条）。

## [ ] F-1 AI 助手「模型 / 思考强度」菜单被压成竖条（文字逐字折行）

> **★ 拍板（2026-10-16）**：**先不修，随台账攒批** —— 处置方向仍待定（届时在下方 A/B/C 里选）。截图为**工作台页面形态（宽宿主）**下的复现，即下方「与宿主宽窄无关」那条已由开发负责人实测确认。

**提出（2026-10-16，开发负责人原话）**：「发现了第一个bug了，AI助手的模型选择框比例显示不正确」（附截图）

**现象**：AI 助手输入区底部点模型按钮（显示「默认 ⌄」）弹出的浮层被压成约 70px 宽的竖条：

- 表头「回答模型 · 仅本任务生效」按 **4 字一行**折成 4 行；
- 每个模型行只看得见供应商名的头一两个字（截图里连续一排 `OpenCode` 全被截断，看不到模型名）；
- 底部「思考强度」折成竖排，四个强度按钮只剩最左一个可见，且它自身又折成「关 / 闭」两行。

**期望**：宽 280px、模型行一行一个、强度四档横排 —— 即 `src/modules/ai-teaching/index.tsx:2393` 那个**同款菜单**的正常形态。

**定位 / 根因**（静态审计，**未改码**）：

两处菜单**逐行同构，只差一个类**：

| 位置 | 弹层根节点类名 |
|---|---|
| `src/modules/ai-teaching/index.tsx:2393`（对照，正常） | `absolute bottom-full right-0 mb-1.5 w-[280px] z-30 …` |
| `src/modules/ai-assistant/index.tsx:446`（报障） | `… w-[280px] max-w-full z-30 …` ← 多这一个类 |

`max-w-full` = `max-width: 100%`，而百分比 `max-width` 是相对**包含块**解析的 —— 绝对定位元素的包含块是**最近的定位祖先**，这里是按钮外面那层 `<div className="relative">`（`ai-assistant/index.tsx:431`）。那层又是上一行 flex 行（`:429`，`relative flex items-center gap-2`）里的 **flex item**，宽度收缩到按钮本身 ≈ 70px（按钮内容 = `Bot` 图标 + `max-w-[140px] truncate` 的模型名，截图里模型名是「默认」两字）。

⇒ `w-[280px]` 被 `max-width: 100%`（≈70px）直接压掉；`px-3` 再占去 24px，正文只剩 ~46px，10.5px 字号**恰好一行 4 字** —— 与截图每处折行位置完全吻合。

**★ 与宿主宽窄无关（开发负责人已实测确认：截图为宽宿主形态）**：弹层浮在一片宽阔空白上（模块区域本身很宽），宽度照样被压 —— 因为 `max-w-full` 取的是**触发按钮的宽度**，与宿主无关。这也解释了它为什么没在别处暴露。

**引入来源**：`max-w-full` 由 `a71a97f`（v3.9.0 两个新模块，2026-10-16 16:06）随 AI 助手模块一起进来，**不是**本次 aiTeaching 合并引入的。

**性质**：真 UI 缺陷（弹层宽度解析错）。看起来像是「怕弹层溢出窄宿主」加的保险，但 `max-w-full` 不是干这个的工具 —— 它相对触发按钮，而不是面板。

**处置方向**（**拍板：先不修**，方向待选）：

| 方案 | 做法 | 代价 / 风险 |
|---|---|---|
| **A. 最小改动** | 删掉 `max-w-full`，与 AI 教学对齐 | AI 助手有 `sidebarHosted` 托管形态（`ai-assistant/index.tsx:295` 走 portal 进宿主侧栏），宿主窄时 280px 弹层会从面板左缘溢出 |
| **B. 走仓库既有正解（推荐）** | 与 `AssistantEntry`（同一功能区的兄弟菜单）同款：`useAnchoredMenu`（`src/lib/useAnchoredMenu.ts`）+ `createPortal` 到 body | 改动大于 A；但该 hook 会按**实测高度**上下翻折、并把 `left/top` **clamp 进视口**，一次解掉「窄宿主溢出 + 被裁剪祖先吃掉」两类问题。先例：`docs/v3.4.0-feedback.md` F-2；`AssistantPanel/AssistantEntry.tsx:17` 原话「彻底脱离裁剪祖先」 |
| **C. 折中** | 保留内置定位，把 `max-w-full` 换成相对**视口**的上限（如 `max-w-[min(280px,calc(100vw-24px))]`） | 不解决「包含块是按钮」这一层：`right-0` 仍以按钮为基准，面板左缘溢出照旧 |

**待补（拍板方向前唯一缺的信息）**：**窄宿主形态仍未验** —— AI 助手被托管进宿主侧栏时（`ai-assistant/index.tsx:295` 走 portal）弹层表现如何。这决定方案 A 是否可用；若窄宿主下 A 会溢出，则直接走 B。

> 「本 bug 只在窄宿主出现」这种可能已被排除：宽宿主形态实测同样复现（见上）。
