## 一、总原则（全部来自原型，不另发明）

1. **供应商 = 端点，账号 = 端点内部的第二层。**
   模型 spec 是 `providerId:modelId`，指向的是**端点 id** —— 所以切换当前账号时，
   5 处模型槽位（对话默认 / AI 助手 / 编辑器续写 / 长对话压缩 / 视觉转写）**一处都不用改**。
   第 6 处（会话自己的覆盖）归会话管，与本页无关。
2. **Key 加密且不可回读**（渲染层只拿得到 `hasKey`）→ 换账号时**无法把旧 Key 读出来搬过去**，
   因此每个账号必须有**自己独立的永久 Key 槽**。这条决定了"账号"不能做成 UI 上的临时状态。
3. **端点可用 = 端点启用 且 至少一个账号可用**（账号启用 + 有 Key；`ollama` 免 Key）。
   不可用端点的模型**不进入模型选择器** —— 避免"选得到却调不通"。
   端点卡片上要显式写出这条因果，不能让用户自己猜为什么模型不见了。
4. **预设携带 5 样**，而不只是省打字：名称与品牌色 / 接口地址 / **协议类型** /
   **必需的请求头** / **模型怎么录入的指路**。
   后三样是"用户不可能知道的东西"——opencode 要 `x-opencode-session` 路由头、
   两端点协议不同；火山方舟要粘**接入点 ID**（`ep-…`）而不是选一个模型名。
5. **预设里地址真伪要标注。** 原型对无法在线核实的地址标 `unverified` 并在卡上明说。
   本机 `web_search` 仍是坏的（HTTP 401），所以：能核实的（opencode 官方 Go 端点，
   已从官方文档读到）不标；核实不了的照原型标出来，**不假装核实过**。

数据层改动（`electron/lib/llmService.ts`）：

```ts
interface ProviderAccount {
  id: string
  name: string
  keyEncrypted: string      // 永不出主进程
  enabled: boolean
  lastLatencyMs?: number
  lastTestedAt?: string     // 展示成「2 分钟前 / 昨天」
}
interface ProviderConfig {
  accounts?: ProviderAccount[]
  activeAccountId?: string
  apiKeyEncrypted: string   // 保留：写盘时同步为**当前账号**的密文，兼容旧读法
}
```

- **迁移**：读盘时 `accounts` 为空且 `apiKeyEncrypted` 非空 → 生成一个账号
  `{name:'默认', keyEncrypted: apiKeyEncrypted, enabled:true}` 并设为 `activeAccountId`。
  用户明确说过"没有用户，老记录直接退役都行"，所以只做这一条保守迁移，不写多版本迁移框架。
- **取 Key 路径收口**：所有解密点（`authHeaders` / `anthropicHeaders` / `visionChat` / `testConnection`）
  统一走 `activeKeyOf(p)`，不再直接读 `p.apiKeyEncrypted`。
- **新增 IPC**：`llm:addAccount` / `llm:updateAccount`（改名 / 换 Key / 启停）/
  `llm:removeAccount` / `llm:setActiveAccount` / `llm:testAccount`。
- **不外泄**：`sanitizeInfo` 只给 `{id,name,enabled,hasKey,lastLatencyMs,lastTestedAt}`。

### 第 5 刀的三处判断（都记在这里，免得下轮当成漏做）

1. **用量页没有「高级」可折**：原型 `paneUsage` 里没有 adv 分组，该页只有"工具调用量（含上限）"

2. **对话页的「高级」改成常显分块**：原型把「深度思考 · 单次任务预算 · 长对话压缩」画成折叠，

3. **「复位」是我按语义补的，原型没定义**：`tmp/ai-settings-proto` 全部产物（含 12 张 DOM 快照）
   搜不到「复位」二字，它是从原型截图里读出来的一个按钮（位置在页签行右侧）。所以定义为
   **恢复当前页签的默认值**，并且 `level:'danger'` 的键一律不参与 —— 权限页因此范围为空、
   按钮置灰。若你要的是别的语义（例如"只复位高级里的项"或"整个 AI 大类回默认"），说一声即可改。

**第 3 刀的两处补充（原型没有、但原有能力不能丢）**：

1. 场景表每行多一个「**测试这个模型**」—— 原型只有供应商级与账号级测试，而"某个模型能不能真调通"
   只有发一次最小补全才知道（这条能力原先就存在，不该因为改版而丢掉）。
2. 场景表的第五行「图片视觉转写」把控件从教学页**并了过来**，教学页只留一句指路 ——

**第 4 刀的一处补充**：「完全信任」预设是**行内两步确认**（点一次变"再点一次"）——
原型直接执行，但一次点击改 8 个模块的写入权限属于"不可忽视的一步"，按铁律 25 行内确认。
另外把模块清单与档位语义抽进 `src/lib/aiPermPresets.ts`（零依赖），契约才能真跑那三条不变量：
`all` 不给没有写操作的模块发写权限、`safe` 连仓库文件一起收回只读、`parsePerms` 必须保留
`terminal` 键（它不在本页渲染，却在同一份 JSON 里管终端工具的档位 —— 丢掉它等于改任一模块权限
就把终端权限静默抹掉）。

**两处与原型的偏离（都是有理由的，写在这里免得下轮当成漏做）**：

1. **「高级」不做折叠、只做常显小节。** 原型把它画成可折叠。但折起来时内层子树根本不挂载
   （铁律 13 的 Collapsible 是"延迟卸载"而非"常驻 DOM"），锚点就不在 DOM 里 ——
   而 `sofficePath` / 网页抓取两项都是 `ui:true` + anchor，也就是**设置搜索的落点**：
   折叠等于把 `terminalAiExec` 那个"搜得到却没有入口"的病再犯一次。
   规则定死：**可搜索的设置项一律常显；折叠只用于 `ui:false` 的低频项**。
2. **`agentCompressModelId` 的归位挪到第 3 刀**（原型划给「模型 · 场景分配表」）。
   场景表本体就是第 3 刀，现在单独把它挪过去只会挪两次；契约里它暂列 PENDING。

**顺带查出并修掉的一个真 bug**：`aiToolMonthlyLimit` 的 `aiTab` 写着 `tools`，
但它的锚点 `aiTools.monthlyLimit` 渲染在**用量**页 —— 设置搜索「月度调用上限」会跳到工具页、
**点进去没有落点**（就是 `terminalAiExec` 那一类）。已改 `usage`，并由 §6 的去向表锁住。

## 三、计划中提及、但不在原型里改的既有 bug

**`src/lib/modelNames.ts` 的 `prettyModelName()` 会把品牌词之后的每一段都 `toUpperCase`**
（`parts.slice(1).map(p => p.toUpperCase())`）。后果是这些字符串直接出现在「默认模型」下拉与
模型选择器里，让列表看起来像没做完：

- `deepseek-chat` → **DeepSeek CHAT**（应为 `DeepSeek Chat`）
- `deepseek-reasoner` → **DeepSeek REASONER**
- `kimi-k2-turbo` → **Kimi K2 TURBO**

原型按**修好之后**的样子渲染（其 `capTail`：只对纯版本号段全大写，如 `5.2` / `v4` / `k2`，
其余词首字母大写）。**本次不改原型文件**，直接按修好的口径落码；该函数没有契约脚本，属低风险小改。

## 六、第 6 刀 · 文案减负（2026-10-13 追加，用户反馈）

用户看完成品后的原话：「碍眼的注释说明之类的还是有些多，看着感觉比以前更加杂乱了」。
根因是前五刀每一节都顺手写了一段解释（为什么这么设计 / 原来在哪 / 边界在哪），
五刀叠起来整页读下来是散文，控件反被埋住。处理办法不另发明，走
`docs/help-disclosure-pattern.md` 形态 B —— **说明一字不删，只是默认收起**，
新建 `src/modules/settings/views/SectionHead.tsx`（标题 + 悬停展开说明 + 右侧操作位）。

三条判据（本次实际执行的分类，共 64 处替换 / 7 个文件）：

| 类别 | 处置 | 例 |
|---|---|---|
| 复述控件标签的句子 | **删** | 「本自然月内所有 AI 工具调用次数…」当两行标签已经写着页数与间隔时 |
| 开发者视角的设计理由 | **删** | 「它们都参与设置搜索，所以做成常显小节而非折叠…」（这话是给我自己看的） |
| 过期指路 / 历史括注 | **删** | 「在『模型』页签的『对话输出』里设置」（该分区已改名）；「替代原来的『手填 ID 列表』」 |
| 有信息量的说明（代价 / 因果 / 边界） | **收进悬停** | 终端执行的两道门、加第二个账号为什么 Key 互不覆盖、opencode 会话头是什么 |
| 空态引导 · 不可逆风险警告 · 动态状态 | **保持常驻** | 「尚未配置供应商」、写入权限「直接生效」警告、吉祥物五种空态、检测/测试结果 |

两处刻意的取舍：

1. **悬停感应范围只给标题行那一小条**，不是整个小节。原型的 B 形态是「悬停整卡」，
   但设置页的小节里往往有长列表与输入框 —— 整块响应会在鼠标划过控件时把下面的内容顶走，
   比常驻还烦。
2. **没有可说的就删干净，不留半句 + 一个 ⓘ**。为了"有个图标"而保留半句话，等于没减负。

回归闸：`.AGENT/scripts/settings/verify-ai-tab-anchors.mjs` §8 四条 ——
标题后不得紧跟常驻说明段（段首是插值数据行的除外）、SectionHead 至少被 5 个视图使用、
已删文案不许回来、空态与不可逆警告必须常驻。
两向都有刹车：只查"少了段落"会纵容把说明删光，只查"有悬停"会纵容段落回来。

### 决策变更（2026-10-13 晚）

- **术语替换被推翻**。§二 第 5 刀曾记「术语替换（原型 §术语太多）」：`maxTokens` → 单次回复上限、
  最大推理轮数 → 单次任务最多思考几轮、单次 token 预算 → 单次任务花费上限、
  历史上下文预算 → 带多少历史对话、自动压缩触发线 → 用掉多少历史就触发总结、
  历史自动压缩 → 长对话先总结。用户看完成品后的判断是「标签要术语，说明要书面语」——
  这两个诉求针对的是两样东西，此前把它们混在一起做了。
- 现状：标签全部换回术语（`单次 maxTokens 上限` / `最大推理轮数` / `单次 token 预算` /
  `历史上下文预算` / `自动压缩触发线(%)` / `历史自动压缩`）；
  **口语叫法保留在 `SETTINGS[].keywords`**，两种叫法在设置搜索里都能命中。
