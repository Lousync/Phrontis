## [ ] F-1 AI 用「分类名」建知识页：作用域目录不在分类索引里 → 应用变更失败

### 现象

1. 用户让 AI 把一段分析「记录一下」。模型调用 `builtin.knowledge.create-page`，参数为
   `{ title: "待优化：app.asar 体积 491MB", categoryName: "感悟与心得", contentMd: "..." }`。
2. 变更方案卡出现「创建知识库页面 · knowledge：{...}」，点「应用 1」后右下角 Toast
   **「应用变更失败」**，右栏「改动文件」仍是 0 条，页面没有创建。
3. 用户说「似乎创建错误了，你再创建一下」，模型重新暂存了一次；再点应用，仍然失败。
4. 从用户视角看：AI 明明先 `vault.list` 到了「感悟与心得」目录，也说「目录目前确认为空」，
   但就是写不进去。

### 复现证据（本机）

- 任务文件：`/home/lousync/生活与记录/.knowbase/assistant/tasks/51688f34-1cbf-454b-848d-e6d6f968b3be.json`
  - 两条 op 都是 `builtin.knowledge.create-page`，参数完全一致，`status` 最终都是 `rejected`；
  - `appliedAt` 却被写成 `2026-10-28T06:52:50.227Z`（见 F-3）。
- 工具审计：`/home/lousync/.config/knowbase/data/plugin-audit.json`
  - `14:51:47` 与 `14:52:50` 两条 `tool.invoke`，`ok = false`，`error` 均为：
    **`未找到分类「感悟与心得」，可省略 categoryName 存入未分类`**。
  - 同会话 `14:51:02` / `14:52:13` 的 `builtin.vault.list {"path":"感悟与心得"}` 都是 `ok = true`。
- 分类表：`/home/lousync/生活与记录/.knowbase/modules/knowledge/categories.json` 共 110 条顶层/子级节点，
  **没有「感悟与心得」**。
- 磁盘：`/home/lousync/生活与记录/感悟与心得/` 存在，**是空目录**（目录创建于 2026-10-28 13:32，
  与 `categories.json` 的最后写入时间 11:41 对不上）。

### 调用链与直接原因

1. 渲染层 `aiAssistantPlanApply` → 主进程 `aiAssistant:plan:apply` → `applyPlan()`
   （`electron/lib/aiAssistantPlan.ts:147`）。
2. `applyPlan` 对 `kind='tool'` 的 op **重新调用工具**
   （`electron/lib/aiAssistantPlan.ts:159-169`）：
   ```ts
   const exec = await invokeToolInternal(op.tool, args, '', { sessionId, apply: true, ... })
   if (!exec.ok) throw new Error(`${op.tool} 应用失败：${exec.message}`)
   ```
3. 工具 handler 用 `categoryName` 在分类索引里找目录
   （`electron/lib/builtinTools.ts:1013-1017`）：
   ```ts
   const cat = vaultGetCategories().find(c => c.name === catName && c.categoryType !== 'space')
   if (!cat) throw new Error(`未找到分类「${catName}」，可省略 categoryName 存入未分类`)
   ```
4. `vaultGetCategories()` 返回的是 `getKnowledgeIndex().categories`
   （`electron/lib/kbStore/knowledgeVaultRepo.ts:144-150`），而索引里的目录节点**只来自「已有知识页文件所在的目录」**
   （`electron/lib/kbStore/knowledgeIndex.ts:616-617`）：
   ```ts
   const dirs = [...new Set(docs.map((d) => dirRelOf(d.rel)).filter((d) => d && d !== KB_INBOX_DIR))].sort()
   const { created, claimed, staleIds } = ensureDirCategories(dirs, categories, current.rootPath)
   ```
   空目录没有任何 `docs` 条目 → 不会进入 `dirs` → 不会被 `ensureDirCategories()` 补建为分类节点。
5. 这条错误被 `aiTools` 捕获成 `{ ok: false, message }`，`applyPlan` 再抛出，IPC 拒绝，
   渲染层只剩一句「应用变更失败」（`src/components/shared/AssistantPanel/useAssistantChat.ts:1038-1040`）。

### 根因（分层）

**A. 直接原因**：`categoryName` 在分类索引中查不到「感悟与心得」。

**B. 为什么查不到的两种可能，都指向同一处设计缺口**：

- 该目录是通过知识库「新建目录」建的（`src/modules/knowledge/index.tsx:1113` 只调 `workspaceMkdir`，
  **不写 `categories.json`**），空目录又不会被索引派生 → 分类索引永远没有它；
- 或目录是在系统文件管理器里直接建的，同样不会进分类索引。

**C. 两套「目录」命名空间没有对齐（核心）**：

| 消费方 | 数据来源 | 是否包含空目录 / 普通磁盘目录 |
|---|---|---|
| AI 助手作用域面板（`ScopePane`） | `workspaceListDir` 直接读磁盘 | **是** |
| `builtin.vault.list` | `workspaceManager` 直接读磁盘 | **是** |
| `builtin.knowledge.create-page` 的 `categoryName` | `getKnowledgeIndex().categories`（派生自索引文件） | **否** |

模型在 `vault.list` / 作用域里看到的「目录存在」证据，与写工具使用的分类索引不是同一套数据；
模型没有任何理由怀疑 `categoryName` 会失效，用户也看到目录明明在那儿。

**D. 即便目录进了分类索引，仍有两条隐藏限制**：

- `categoryType !== 'space'`：**学习空间根**永远不能作为 `create-page` 的目标（这是当前代码写死的）；
- 只用 `name` 精确匹配，不校验路径：不同空间下存在同名目录时，`find()` 取第一个命中，
  页面可能落到**错误的空间**（`categories.json` 里同名节点并不罕见）。

**E. 校验时机太晚**：

- 暂存层（`electron/lib/aiTools.ts:336-364`）只做参数 schema 校验，**不解析 `categoryName`**，
  所以方案卡展示时一切正常；
- 真正解析发生在用户点「应用」之后，失败与模型的推理轮次已经脱节：
  **模型收不到这个错误**，下一轮仍会用同一个错误参数重试（本机任务文件里两条一模一样的 op 就是证据）。

### 影响面

- `builtin.knowledge.create-page`（`electron/lib/builtinTools.ts:988-1028`）；
- `builtin.quiz.gen-paper` 的 `categoryName` 是同一份实现（`electron/lib/builtinTools.ts:3170-3175`），
  同样会失败；
- 所有「作用域是磁盘目录、写工具按分类名定位」的 AI 流程都受影响——这是**结构性**问题，不是单次参数写错。

### 处置方向（未落码，待拍板）

1. **首选：让 `create-page` 支持路径定位**。新增可选参数 `categoryPath`（仓库相对目录，如
   `感悟与心得`），按 `path` 精确解析；目录存在但索引没有节点时，允许直接把页面写进该目录
   （文件落盘后索引会自然派生分类节点）。`categoryName` 保留兼容。
2. **暂存期校验**：在 `stageOp` 之前把 `categoryName` 解析成 `categoryId` 并存入 args；
   解析失败就**当场返回工具错误**给模型，让它在本轮内改参数，而不是等用户点应用才炸。
3. **放开 space 根**：明确「学习空间根能不能直接放页面」的产品口径；能放就删掉 `!== 'space'`，
   不能放就在工具描述里写清「请指定空间内的分类」并给出可用分类列表。
4. **同名歧义**：`categoryName` 命中多个节点时，要求调用方补 `categoryPath`，或在结果里回报歧义，
   不要静默取第一个。
5. **失败反馈**：`applyPlan` 失败时把错误写回会话（一条 tool/system 消息），让模型下一轮能自我修正；
   至少在变更方案卡上标红这一条并显示原始错误。

### 验证建议

- 契约脚本（新增或用 `.AGENT/scripts/ai-assistant/verify-plan-rollback.mjs` 扩展）覆盖：
  1. 空目录（不在 `categories.json`）→ 建页应成功，文件落在该目录；
  2. 学习空间根 → 按拍板口径成功或给出明确拒绝；
  3. 两个不同空间下的同名目录 → 必须落到指定路径；
  4. 不存在的分类名 → **暂存期**就返回错误，而不是应用期；
  5. 应用失败 → op 不能停留在 `pending`（见 F-3）。
- 实机：知识库「新建目录」建一个空目录 → AI 助手作用域选中它 → 让 AI 建页 → 应用。

## [ ] F-2 AI 助手模块内划词「问 AI」被右栏用量面板截走，选段无处可落

### 现象

1. 在「AI助手」模块（左栏书签进入的工作台模块，`activeTab = 'aiAssistant'`）的回复里划选一段文字；
2. 浮条点「问 AI」；
3. **模块自己的输入框没有任何变化**；右侧栏（AI Tab）本来就是「今日消耗 / 改动文件」用量面板，
   看不到输入框；
4. 若右栏原本折叠，点「问 AI」会把右栏展开——展开后仍然是用量面板，像是「要在右边回答，但右边是计费数据」；
5. 选段并没有丢：它被静默塞进了右栏 docked 对话的引用胶囊里，
   **切到别的模块后**右栏 AI 输入区会突然冒出这条引用。

期望行为（与 AI 教学 / AI 对话页一致）：选段作为**引用胶囊**进入当前会话的输入区上方，不自动发送。

### 定位

1. 全局「问 AI」浮钮在 `AssistantPanel`，点击走 `askSelection()`
   （`src/components/shared/AssistantPanel/index.tsx:243-260`）：
   ```ts
   const host = getSelectionAskHost()
   if (host) { if (host.accept()) { host.ask(text); return } }
   // 回退：收进悬浮侧栏引用胶囊 + openPanel()
   ```
2. 当前注册的宿主只有三处：
   - AI 教学：`src/modules/ai-teaching/index.tsx:813-830`，`useEffect` 依赖 `isActive`，**只在教学模块激活时入栈**；
   - AI 对话整页：`src/components/shared/AssistantPanel/ChatBody.tsx:972-978`，`active` 为真时入栈；
   - App 右栏宿主：`src/App.tsx:1657`，**常驻注册**，判定条件只有三条
     （`src/App.tsx:1645-1648`）：
     ```ts
     accept: () => !fullWindowTab && activeTab !== 'aiChat'
       && !wbLayout.panelTabsHidden.includes('ai')
     ```
     **没有排除 `aiAssistant`**。
3. 「AI助手」模块本身**没有注册任何划词宿主**（全仓 `registerSelectionAskHost` 的调用点只有上表三处）。
4. 于是划词落到 App 宿主，`ask()` 做三件事（`src/App.tsx:1649-1655`）：
   关闭悬浮层 → `rightTab: 'ai'` + 展开右栏 → `setPendingRightAsk(text)`。
5. 右栏拿到 `pendingAsk` 后无条件收进引用胶囊
   （`src/components/workbench/WorkbenchRightPanel.tsx:199-209`），并尝试
   `aiChat.inputRef.current?.focus()`；
6. 但同一文件在 `aiUsagePanel === true` 时渲染的是 `AiUsagePanel` 而不是 `ChatBody`
   （`src/components/workbench/WorkbenchRightPanel.tsx:515-525`），而 App 给它的判据是
   `aiUsagePanel={activeTab === 'aiChat' || activeTab === 'aiAssistant'}`（`src/App.tsx:1926`）。
   → 引用胶囊被存在一个**没有渲染输入框**的控制器里，focus 也落在一个不可见的 textarea 上。

### 根因

- App 右栏宿主的 `accept()` 写于「只有 AI 对话页有自己的输入框」的时期；v3.9.0 新增的「AI助手」模块
  虽然复用同一批会话，但有自己的底部输入框，**既没被排除、也没注册自己的宿主**。
- `aiUsagePanel` 这个 prop 把两件事混成了一个判据：
  1. 「中间主体已经是对话」→ 右栏不该再放一份小对话；
  2. 「右栏 AI Tab 没有输入框」。
  `aiChat` 场景下第 1 条成立但有 AiChatTab 宿主先接管，所以没事；
  `aiAssistant` 场景下第 1 条成立、却没有任何宿主接管 → 选段必然掉进「无输入框」的右栏。
- 这是**路由缺口**，不是用量面板本身的错；用量面板只是把「选段没有落点」变得肉眼可见。

### 影响面

- 「AI助手」模块内所有划词「问 AI」；
- 同类风险：今后任何「自带输入框 + 复用统一会话」的新模块，只要忘了注册宿主，就会复现同样的静默错位；
- 翻译不受影响（翻译卡片不依赖输入框）。

### 处置方向（未落码，待拍板）

1. **模块就地接管（首选）**：在 `src/modules/ai-assistant/index.tsx` 注册 `SelectionAskHost`（`isActive` 门），
   选段进模块自己的引用胶囊；模块输入区需要补 `QuoteChips` 与发送前 `buildQuotedBody()` 合并逻辑
   （与 `AiChatTab` / AI 教学同一套 `selQuotes.ts`）。
2. **宿主收口**：App 右栏宿主的 `accept()` 排除 `aiAssistant`（以及今后所有「自带输入框」的标签），
   避免选段被用量面板吞掉。
3. **防御性兜底**：`WorkbenchRightPanel` 在 `aiUsagePanel === true` 时不应消费 `pendingAsk`；
   至少要给一次 Toast「当前模块请直接在模块输入框提问」，不能静默存进隐藏控制器。
4. **防漂移**：把「哪些 Tab 自带对话输入框」收进 `src/lib/appModules.ts` 一类的单一清单，
   避免 App / 模块 / 右栏三处各写一份条件（现有 `AI_ASSISTANT_SHORTCUT_DISABLED` 是同一类问题的先例）。

### 验证建议

- 手动矩阵：`aiChat` / `aiAssistant` / `aiTeaching` / 普通知识库页 × 右栏折叠/展开 × 右栏 AI Tab 显示/隐藏；
  每条都应满足「选段只落在**当前可见**对话的输入区，且不自动发送」。
- 断言隐藏状态不残留：在 `aiAssistant` 划词后切到知识库，右栏 AI 输入区**不应**突然出现上次的引用。

## [ ] F-3 变更方案的展示 / 失败状态 / 模型反馈 / 幂等（F-1 暴露出的次生问题）

### 现象与证据

1. **卡片展示的是原始 JSON**：方案摘要由
   `summarizeArgs(cleanArgs)`（默认 200 字，`electron/lib/pluginAudit.ts:114-118`）拼成
   `${tool.title} · ${module}：${JSON}`（`electron/lib/aiTools.ts:344`）。
   屏幕上看到的是带 `\n` 转义、英文参数名的长串，用户很难判断「到底要建什么」。
2. **失败了却标了 `appliedAt`**：`applyPlan` 的 `finally` 无条件写
   `plan.appliedAt = new Date().toISOString()`（`electron/lib/aiAssistantPlan.ts:187-191`）。
   本机任务文件里 0 条成功、2 条 `rejected`，`appliedAt` 仍然有值。
3. **失败 op 没有失败状态**：抛出发生在 `op.status = 'applied'` 之前，op 会留在 `pending`；
   用户再点「应用」会重放同一条，直到手动丢弃/停止。没有「失败」这个状态，也没有失败原因挂在卡片上。
4. **模型对应用失败无感知**：`applyPlan` 的错误只返回渲染层
   （`useAssistantChat.ts:1038-1040`），没有写回会话；模型下一轮仍以「已成功暂存」为前提，
   于是出现本机任务文件里两条**完全相同**的 `create-page` op——如果第一次应用成功，第二次就会造出重复页面。
5. **暂存不留审计**：通用暂存分支在 `appendAudit()` 之前 return（`electron/lib/aiTools.ts:336-364`），
   暂存动作在 `plugin-audit.json` 里没有任何记录；排查时只能靠任务 JSON。
6. **晚失败还有同类**：月度调用上限（`electron/lib/aiTools.ts:366+`）和模块权限
   （`electron/lib/aiTools.ts:305-318`）都在**应用期**才检查；暂存时都通过，应用时可能突然失败。

### 处置方向（待拍板）

- 方案卡按 `kind` 渲染人类可读摘要（标题 + 目标目录 + 正文首行/字数），不要直接贴 JSON；
- 增加 `failed` 状态与失败原因字段，失败后不再作为 `pending` 重放；
- `appliedAt` 只在 `applied > 0` 时写（或改名为 `finishedAt` 并另存 `appliedCount`）；
- 应用失败写回会话（一条 tool 结果/系统消息），让模型下一轮能修正；
- 暂存动作补审计（staged / applied / failed 三态）；
- 暂存期做一次「可执行性预检」（分类解析、权限、上限），把晚失败前移。

## 修复记录（2026-10-28，v3.15.2）

### F-1 目标目录解析

- 新增 `electron/lib/knowledgeTargetPure.ts`：`categoryId` / `dirRel`（暂存结果优先）→ `categoryPath` 路径 → `categoryName`（含 space / notebook）→ 磁盘同名根目录兜底；同名多节点优先唯一顶层，否则要求 `categoryPath`。
- `electron/lib/kbStore/knowledgeVaultRepo.ts`：`vaultCreatePage` 支持 `dirRel`；新增 `vaultDirExists`（拒绝绝对路径 / `..` / 隐藏目录段）。
- `builtin.knowledge.create-page` / `builtin.quiz.gen-paper` 改为 **handler 自暂存**（`HANDLER_STAGED_DATA_TOOLS` + `stageToolOp`）：暂存前解析目标，失败当场回给模型；应用时重新校验目录仍在，被删则明确失败。
- 工具 schema 增加 `categoryPath`，description 说明可写入空目录 / 空间根。
- 契约：`.AGENT/scripts/ai-assistant/verify-knowledge-target.mjs`（30 项）。

### F-2 AI 助手模块划词

- `AiAssistantModule` 注册 `SelectionAskHost`（`isActive` 门），选段进 `QuoteChips`；发送时 `buildQuotedBody` 合并、一次性清空。
- App 右栏宿主 `accept()` 排除 `aiAssistant`；`WorkbenchRightPanel` 在 `aiUsagePanel` 态不再消费 `pendingAsk`（防御性兜底）。
- 契约：`verify-unified-assistant.mjs` H 段。

### F-3 变更方案失败路径

- `PlanOp` 增加 `failed` 状态与 `error` 字段；失败项不再作为 `pending` 重放，`rejectPlan` 可一并清掉。
- `appliedAt` 只在 `applied > 0` 时写；失败摘要经 `appendAgentMessage` 写回会话（会话存在时），下一轮模型可见。
- 方案卡摘要改人类可读（`summarizeToolOp`）；暂存动作记 `tool.stage` 审计，handler 自暂存结果记 `staged: true`。
- `ReviewPane` 显示失败数 / 红色状态 / 失败原因；`useAssistantChat` 按失败数弹 Toast 并刷新消息列表。
- 契约：`verify-unified-assistant.mjs` I 段、`verify-plan-rollback.mjs` A3 + D8-D11。
