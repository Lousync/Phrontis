# v3.15.3 反馈：AI 对话切换会话时串场（调查 + 修复）

> 来源：2026-10-29 用户截图反馈 —— 课程助手正在输出，切到知识点对话，旧输出状态跟了过来。
> 分支：`v3.15.3`。状态：**已修**。
> 结论：AI 教学主对话 / 支线面板此前仍用「单活动会话」模型；AI 助手三宿主 / 日程 / 情报 / AI 学堂早已走 N-3 的 `assistantRunStore` 会话桶，没有这个问题。本次把 AI 教学两个面统一迁入同一套会话桶，并退役单槽 hook。

## 一、现象与复现

- 课程助手流式输出中（「思考中…」+ 工具步骤 + 正文增量）；
- 左栏点知识点，进入某段的「知识点对话」；
- 新对话里仍然显示课程助手的「思考中…」、工具步骤和正文增量；
- 输入区仍是停止按钮，旧回答继续往新页面里长；
- 旧会话结束后，新段消息可能被旧会话消息覆盖。

复现路径：

1. 打开 AI 教学 → 课程助手，发一条会触发工具 / 长回答的消息；
2. 回答未结束时，点左栏任一知识点：
   - 已有进行中的段 → `openSegmentBySid()`；
   - 未开段 → 预检确认 → `startSegment()`；
3. 两条路径最终都走 `openSession(sid, title)`，把 `activeId` 切到知识点所在段；
4. 新段立即出现旧会话的流式卡。

## 二、修复前根因（证据，行号以修复前快照为准）

### 1. 运行态是模块级单槽，不是会话级

| 状态 | 修复前位置 | 问题 |
|---|---|---|
| `pending` | `src/modules/ai-teaching/index.tsx:327` | 全局布尔，不区分哪个会话在跑 |
| `streamDraft` | `:901` `useAgentStream(chatIdRef)` | 单草稿，不按会话分桶 |
| `chatIdRef` | `:763` | 单 chatId，切会话不更新 |
| `liveSteps` | `:328` | 单数组，切会话先清空，但旧 run 事件会继续填 |
| `lastChanges` | `:329` | 旧 run 的改动清单会显示在新会话 |
| `artTabs` / `artActive` | `:406` | 旧 run 的工件事件会在新会话重开页签 |

`openSession` 只切 `activeId` / 消息 / `liveSteps` / 工件页签，**没有**清 `pending`、`streamDraft`、`chatIdRef`、`lastChanges`。渲染条件 `pending && streamDraft`（`:2798`）没有「这个草稿属于当前会话」的判定，所以新会话直接复用了旧草稿。停止键（`:2243`）也只看 `pending`，点击后 abort 的是 `chatIdRef.current`（旧 run 的 chatId）。

### 2. 流事件按 chatId 过滤，而 chatId 不随会话切换

- 模块自己的 `onAgentStep`：`if (chatId !== chatIdRef.current) return`；`chatIdRef` 仍是旧 run 的 cid，切到新段后旧 run 的 step 继续写入 `liveSteps`、`artTabs`、`liveImagePending`。
- `useAgentStream` 内部同样按 `chatIdRef.current` 过滤 `agent:stream`，旧 run 的 delta 继续写进同一个 draft。
- 主进程的 `agent:step` / `agent:stream` 载荷同时带 `sessionId`（`electron/lib/agentService.ts:1953`、`:1957`），AI 教学只用了 `chatId`。

### 3. 旧 run 收尾会污染新会话（更严重）

- `sendText` 在发送时捕获 `sid`；切走后 `finishRun(r, sid)` 收到的仍是旧会话 id。
- `finishRun` 的 `finally` 无条件 `endStream()` + `setPending(false)`，全局清运行态。
- `finishRun` 里的 `await refreshMessages(sid)` 会无条件 `messagesSidRef.current = sid` + `setMessages(旧会话 rows)`；旧 run 在新段激活后结束，就会把新段消息替换成旧会话历史。
- 复用一个简单的 `activeIdRef.current === sid` 守卫也不行：`activeIdRef` 是 effect 异步更新的，`openSession` 里 `setActiveId` 后立刻 `await refreshMessages`，首帧会误杀正常加载。需要同步的 desiredSid / 请求令牌。

### 4. 其他同源漏出

- `finishRun` 的 `setLastChanges(旧 run changes)` 会把旧会话改动清单显示在新会话。
- 旧 run 的 visual / mindmap / image 步骤会在新会话重新开「生成中」页签。
- `liveImagePending` 由全局 `liveSteps` 派生，旧生图占位可能出现在新会话。
- 课程树 `CourseRail` 没有运行角标，切走后用户看不到「旧对话仍在跑」。

## 三、修复内容

### 1. AI 教学主对话：接入 `assistantRunStore` 会话桶

- `pending` 改为 `isSessionRunning(activeId)`；`draft` / `liveSteps` 改为 `getRunBucket(activeId)` 的投影。
- 发送 / 继续：`beginRun(sid)`；收尾：`endRun(sid)`。
- 订阅 `subscribeAssistantRunState`；后台完成时对当前会话 `takeEndedFor(sid)` 补一次 `refreshMessages`。
- 查看登记 `markSessionViewed(activeId)` / `unmarkSessionViewed`，且只在 AI 教学 Tab 可见时登记。
- `onAgentStep` 工件副作用改为按 `sessionId === activeIdRef.current` 过滤，不再按 chatId。
- 停止键改 `agentAbortSession(sid)`，删除 `chatIdRef`。

### 2. 旧 run 晚到不再污染新会话

- `openSession` **同步**写 `activeIdRef.current = sid`，不等 `useEffect`；切到不同会话时先清空 `messages` / `messagesSidRef`，避免 IPC 拉取期间旧会话内容在新标题下闪现。
- `refreshMessages` 在 await 前后都校验 `activeIdRef.current === sid`；旧 run 晚到的刷新直接 no-op。
- `finishRun` 按 `activeIdRef.current === sid` 决定是否更新 `messages` / `lastChanges` / 工件页签 / 复习讲义；`endRun(sid)` 无条件执行。
- 关闭 / 切换会话后，旧 run 仍在后台跑；切回时从会话桶恢复实时流。

### 3. AI 教学支线面板：同口径接入

- `SideLanePanel` 的 `pending` / `draft` 改为按 `laneId` 从会话桶读取；发送 / 收尾走 `beginRun(laneId)` / `endRun(laneId)`。
- 停止键改 `agentAbortSession(laneId)`。
- 浮层支线在 `index.tsx` 加 `key={floatLane.laneId}`；右栏支线中心原本就按 `activeId` / `create` 重挂载。
- 面板在新实例挂载前旧 run 已结束：挂载后 `takeEndedFor(laneId)` 补一次消息对齐。

### 4. 单槽 hook 退役

- 删除 `src/components/shared/AssistantPanel/useAgentStream.ts`。
- `StreamBubble` / `MessageList` / `AiLearn` 的 `StreamDraft` 类型改从 `src/lib/agentStreamCore.ts` 导入。
- 从此所有生产面的流式草稿只有一个真源：`assistantRunStore` 的 sessionId 分桶。

### 5. 通用 AI 助手控制器的小修

`useAssistantChat` 的 `regenerate` / `resume` / `editSubmit` 在旧 run 收尾时，`setLastChanges` 增加 `activeIdRef.current === sid` 守卫；消息刷新本来就有 activeId 守卫。

## 五、修复后行为

- 课程助手输出中切到知识点：新段只显示自己的 `pending` / 草稿 / 步骤；旧会话在后台继续。
- 切回课程助手：会从会话桶恢复实时流（若还在跑）或显示最终消息（若已完成）。
- 旧会话结束时：不再覆盖新段消息、改动清单、工件页签；不会在新段弹旧会话的生成占位。
- 停止键只停当前会话；旧会话的后台完成由 `assistantRunStore` 记录未读 / 失败提示（课程树的运行角标暂未接入，见「遗留」）。
- 不同会话可以并行（N-3 口径）；同一会话仍只允许一个 run。

## 七、遗留 / 可选

- 课程树暂未挂运行角标：后台会话完成时没有列表级「转圈 / 蓝点」。数据已在 `assistantRunStore`，后续可给 `CourseRail` 的课程助手 / 段行补 `SessionRunMark`。
- 输入框 `input` 仍是模块级、不随会话切换；这是独立的小串场（未发送文字），本次未动。
- 实机回归重点：课程助手长回答中切知识点 / 切另一个段 / 切到别的模块再回来；旧 run 结束后检查消息归属、改动清单、工件页签。
